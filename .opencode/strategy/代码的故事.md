# 《代码的故事》栏目策略

> 最后更新：2026-05-15
>
> 以编程语言为明线，以计算机如何进入人类生活的每一个角落为暗线。每种语言都是一个时代的切片——它为什么被创造、它解决了什么问题、它留下了什么。

---

## 一、栏目定位

**核心理念**：每种编程语言的诞生都是一个具体的工程问题在逼着人创造。

- 不是"编程语言编年史"——不是维基百科式的罗列特性、设计哲学、版本历史
- 是一组**关于人的故事**——谁在什么情况下写了第一行编译器？他当时在解决什么问题？那个问题为什么重要？

**明线**：语言——Fortran → Lisp → C → SQL → C++ → Java → JavaScript → PHP → R → Python → Ruby → Go → Rust

**暗线**：计算如何渗透世界——从军方和研究机构的庞然大物，到办公桌上的 PC，到口袋里的手机，到无处不在的云。

**叙事形式**：每个语言一篇独立故事，第三人称叙事，聚焦**诞生时刻**——创造者面对的问题、做出的取舍、无心插柳的后果。

**风格**：不写语言教程，不比较优劣。写的是：**2012 年 Google 的三个工程师在为什么事情烦到要自己造一门语言？**

### 第一章·计算的觉醒（1950s–1960s）

计算机从实验室走向实用。问题是：**科学家能不能不靠程序员，自己写程序？**

| order | 篇   | 标题                    | 内容                                                                                                                                                                                                                      |
| ----- | ---- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | 主篇 | Fortran：把公式交给机器 | John Backus 在 IBM 领导了第一个高级语言编译器。**核心问题**：IBM 704 的用户是物理学家和数学家，他们不会写汇编。能不能让他们直接写数学公式？Fortran 的答案是"效率接近手写汇编"。1957 年，一行 `y = x + 1` 跑起来了 |
| 2     | 主篇 | Lisp：符号的递归        | John McCarthy 在 MIT 想要一个做 AI 研究的语言。**核心问题**：AI 研究需要处理符号而非数字，需要能修改自己的代码。Lisp 的回答是"代码即数据"。car/cdr、递归、垃圾回收——这些概念 1958 年就有了                        |

---

### 第二章·机器的语言（1970s）

计算机变小了，操作系统崛起了。问题是：**写系统软件的语言应该长什么样？**

| order | 篇   | 标题           | 内容                                                                                                                                                                                                                                                                                                         |
| ----- | ---- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 3     | 主篇 | C：Unix 的血液 | Ken Thompson 和 Dennis Ritchie 在贝尔实验室。**核心问题**：PDP-7 太小，跑不了 Multics。Thompson 决定写一个自己的操作系统。Ritchie 觉得 B 语言太弱，需要一个能把 Unix 移植到不同机器的语言。C 的答案是"在高级语言中保留了对硬件的控制权"。1973 年，Unix 内核用 C 重写——操作系统第一次可以用高级语言写 |

**暗线串联**：Fortran 让科学家摆脱了汇编；C 让系统程序员摆脱了汇编。从计算到系统，计算机开始走出机房。

### 第三章·数据的语言（1970s–1980s）

计算机有了操作系统，能跑程序了。但真正的商业价值藏在**数据管理**里。

| order | 篇   | 标题                  | 内容                                                                                                                                                                                                                                                                 |
| ----- | ---- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4     | 主篇 | SQL：问数据库一个问题 | Edgar Codd 在 IBM San Jose 实验室发表了关系模型论文。**核心问题**：当时的数据库是 CODASYL 网络模型，程序员要写复杂的导航代码才能查到数据。Codd 说"让用户声明他们想要什么，而不是怎么找"。1986 年 SQL 成为标准。从此问数据库不再需要写程序——只需要 `SELECT` |

**暗线串联**：商业计算的核心需求从"计算"变成了"查询"。懂数据比懂代码更值钱。

---

### 第四章·规模化的语言（1980s–1990s）

软件越来越大，一个人写不完了。问题是：**如何管理复杂度？**

| order | 篇   | 标题                  | 内容                                                                                                                                                                                                                                                                                     |
| ----- | ---- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5     | 主篇 | C++：面向对象的工业化 | Bjarne Stroustrup 在贝尔实验室。**核心问题**：Simula 的面向对象很好用，但太慢。C 很快但抽象能力不够。Stroustrup 想要"带类的 C"。1979 年 C with Classes 诞生，1983 年改名 C++。**暗线**：软件工程的第一个危机——代码量爆炸，需要更好的组织方式                               |
| 6     | 主篇 | Java：虚拟机的征服    | James Gosling 在 Sun 想做一个给消费电子用的语言。**核心问题**：机顶盒需要跨平台，C++ 太复杂、指针太危险。Java 的答案是 JVM——一次编写到处运行。1995 年随 Netscape 浏览器发布。**暗线**：互联网需要一种"在服务器上跑、不怕崩溃、不挑操作系统"的语言。Java 正好站在了这个位置 |

**暗线串联**：个人电脑普及，软件从个人作品变成工程产品。面向对象、虚拟机、垃圾回收——这些概念都是"人写不动了"逼出来的。

---

### 第五章·网络的语言（1995–2005）

互联网从信息发布变成了生活平台。问题是：**这个新世界用什么语言来写？**

| order | 篇   | 标题                    | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----- | ---- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7     | 主篇 | JavaScript：十天与十年  | Brendan Eich 在 Netscape 被要求"在浏览器里加一个脚本语言"。**核心问题**：不能让网页纯静态，需要一种能让非专业程序员也在浏览器里写代码的语言。Eich 用 10 天做出了 JavaScript。**暗线**：1995 年它只是个表单验证脚本工具；2015 年它统治了浏览器、服务器（Node.js）、甚至桌面（Electron）。互联网的每一层最终都被 JavaScript 覆盖了                                                                                                                           |
| 8     | 主篇 | PHP：网站的民主化       | Rasmus Lerdorf 在 1994 年用 Perl 写了一套个人主页工具。**核心问题**：做动态网站太难了——CGI、Perl、数据库配置——一个非技术人员几乎不可能独立完成。PHP 的回答是"把代码直接嵌进 HTML"。**暗线**：PHP 让任何人都能搭一个留言板。互联网的"建站权"被下放到了每一个人手上——这是博客、SNS、UGC 浪潮的技术前提                                                                                                                                                 |
| 9     | 主篇 | R：统计学家造了一门语言 | Ross Ihaka 和 Robert Gentleman 在奥克兰大学。**核心问题**：统计学家要做数据分析，但商业统计软件（SAS、SPSS）贵且封闭，通用语言（C、Fortran）又没有统计学的"方言"。R 的答案是"用 S 语言的语法 + 开源社区的包机制"。1993 年起草，1995 年 GPL 发布。**暗线**：数据分析原来只是科研的配角；R 让它成为一门独立的学科——ggplot2 改变了人们"看数据"的方式、R Markdown 改变了人们"写分析报告"的方式。一个由两个统计学教授发起的项目，最终定义了数据科学的基础设施 |
| 10    | 上篇 | Python：胶水语言的逆袭  | Guido van Rossum 在 1989 年圣诞节做了一个"更好的脚本语言"。**核心问题**：ABC 语言很好但没人用——Python 的答案是"可读性高于一切"。但它真正的命运转折点是被人当作"胶水语言"——把 C、Fortran 的库粘在一起。NumPy/SciPy 选择它做科学计算的上层接口，Django/Flask 选择它做 Web 框架，运维工程师选择它做自动化脚本。**暗线钩子**：当其他语言在争抢互联网时，Python 正在实验室和服务器机房被人悄悄捡起来——这些人在二十年后会用 Python 发动一场 AI 革命                                                                           |
| 11    | 下篇 | Python：AI 帝国的方言   | 2015 年 Google 发布了 TensorFlow，2016 年 Facebook 发布了 PyTorch——它们都选择了 Python 作为前端语言。**核心问题**：深度学习框架为什么不用 C++ 或 Lua？答案是"研究者的需求优先"——实验需要快速迭代，Python 的可读性和胶水能力恰好适合"用 C++ 跑底层、用 Python 调模型"的分层架构。PyTorch 最终打赢 TensorFlow，很大程度上是因为它"更像 Python"。**暗线**：Python 从"胶水"变成了 AI 时代的"方言"——不是最快的语言，但所有做 AI 的人都在说它                                                                                                                                  |
| 12    | 主篇 | Ruby：快乐的代价        | Yukihiro Matsumoto（Matz）在 1995 年想要一种"比 Perl 更强大、比 Python 更面向对象"的语言。**核心问题**：程序员编程是为了快乐。Ruby 的答案是"最小意外原则"——让你写代码的时候觉得爽。2004 年 Ruby on Rails 问世，"约定优于配置"的哲学把 Web 开发速度拉到极致。**暗线**：但 Ruby 永远没解决性能问题。它证明了"快乐"是有代价的                                                                                                                               |

**暗线串联**：本科幻的五章。互联网从 HTML 页面变成了生活基础设施——购物、社交、打车、外卖。每种语言都在抢一个生态位：JavaScript 在浏览器、PHP 在网站、Ruby 在快速原型。而 R 和 Python 是这章里的异类——它们和 web 无关，它们的战场在数据。R 的故事是**统计学家悄悄造了一门自己的语言**；Python 的故事分上下两篇——上篇是**被当作胶水的意外帝国**，下篇在第六章等待它的是**AI 时代的王座**。

### 第六章·当代的语言（2009–）

规模空前。问题是：**Google、Amazon、Facebook 的体量需要什么语言？**

| order | 篇   | 标题                  | 内容                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----- | ---- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 13    | 主篇 | Go：Google 的工程哲学 | Robert Griesemer、Rob Pike、Ken Thompson 在 2007 年受够了。**核心问题**：Google 的代码库——C++ 编译太慢、依赖管理是噩梦、Java 太啰嗦、并发太难写。Go 的答案是"简单到可以在一个下午学会"。goroutine、interface、gofmt——设计目标不是表达力，是**工程师效率 × 可维护性**。2009 年开源，2012 年 1.0。**暗线**：云计算需要一种"编译快、部署简单、天生并发"的语言。Go 恰好做了这件事 |
| 14    | 主篇 | Rust：重写一切的野心  | Graydon Hoare 在 Mozilla 做了一个个人项目。**核心问题**：Firefox 的 C++ 代码有大量内存安全漏洞。能不能有一种语言，像 C++ 一样快、保证内存安全、但没有垃圾回收？Rust 的答案是"所有权系统"——编译器在编译时检查内存的谁借了谁。2015 年 1.0 发布。**暗线**：安全成了系统编程的第一优先级。Linux 内核开始接纳 Rust、Android 支持 Rust——用了 50 年，C 的替代者来了                         |

**暗线串联**：计算到了"无处不有"的阶段——每个手机、每台服务器、每个 IoT 设备都在跑代码。Google 需要工程效率，Mozilla 需要内存安全。语言设计的优先级从"能不能做到"变成了"能不能不出错"。

## 三、暗线梳理

这暗线不是一条直线，是三条交织的线：

**① 计算机的物理形态变迁**

```
房间大小 → 桌面大小 → 口袋大小 → 云端（无处不在）
Fortran/Lisp       C/C++         Java/JS/PHP/R    Go/Rust
（大型机时代）  （小型机/PC）  （互联网+数据时代）（云计算时代）
```

**② 谁在写代码**

```
数学家/物理学家  →  系统工程师  →  企业开发者  →  网页设计师   →  科研/分析   →  人人
Fortran/Lisp         C/C++          Java/C++       JS/PHP        R/Python     Go/Rust
```

**③ 代码在解决什么问题**

```
科学计算 → 操作系统 → 数据管理 → 软件工程 → 网络服务 → 统计分析 → 基础设施
Fortran    C          SQL         C++        JS/PHP     R          Go/Rust
                                              Python (数据分析与AI)
```

最终暗线是：**编程语言的历史就是计算机不断降低使用门槛、不断扩大影响范围的历史。**

## 六、写作风格

### 前言与后记的特殊风格

前言和后记采用**自媒体博主风**——娓娓道来，亲切自然，像博主在跟读者聊天。不设 Hello World，不按"核心问题→诞生故事→遗产"的结构走。

- **前言**：交代为什么写这个栏目、写给谁看、怎么读。语气像视频博主的开场白——"朋友，欢迎你来到这里"
- **后记**：栏目完结时与读者告别，写写写作过程中的感受、最让自己印象深刻的发现、以及那些没写进去的故事

主篇统一用紧凑的叙事风格（见下文），但前言/后记可以松弛下来，段落短一些，多用人称代词（你、我、我们）。

### 字数

单篇不限字数，以把故事讲完整为准。正常一篇 5500–7000 字，可更长。每篇可设 6-8 个章节小节，把诞生背景、关键人物、设计决策、后续影响、文化现象等维度写透，追求长文阅读的沉浸感。语言故事需要足够的篇幅展开诞生背景、人物困境和技术细节，不要为了凑字数注水，也不要为了省字数砍掉关键的叙事铺垫。

### 每篇的核心问题

- Fortran：科学家能不靠程序员自己编程吗？
- Lisp：计算机只能处理数字还是能处理思想？
- C：高级语言能写操作系统吗？
- SQL：数据库可以"问"而不是"找"吗？
- C++：面向对象能驯服复杂软件吗？
- Java：跨平台是真的可能的还是营销话术？
- JavaScript：浏览器需要一门真正的语言吗？
- PHP：普通人能做网站吗？
- R：统计学家需要自己的语言吗？
- Python（上篇）：一门"可读"的语言能成为最强大的工具吗？
- Python（下篇）：为什么深度学习框架都选择了 Python？
- Ruby：程序员值得拥有"快乐"吗？
- Go：Google 能设计出比 C++ 更好的系统语言吗？
- Rust：没有垃圾回收的安全内存管理是可能的吗？
- 结语：编程语言会被 AI 终结吗？

### 每篇的开头：Hello World

每篇文章以该语言的 Hello World 开篇——这是对 1978 年 K&R C 经典的致敬，也是一种语言气质的第一印象。

```c
/* C */
main() { printf("hello, world\n"); }
```

```python
# Python
print("Hello, World!")
```

```r
# R
print("Hello, World!")
```

一段语法就揭示一种性格：C 的"极简且接近机器"、Python 的"可读到无聊"、Java 的"仪式感"、Lisp 的"前缀表达式"……读者在看到代码的瞬间就能感受到这门语言和之前那门的不同。

**结语是唯一的例外**——当最后一种语言来到自然语言 / AI Coding 面前，Hello World 不需要代码框。只有一行：

```
Hello, World.
```

然后开始这个故事的最后一段。没有代码本身就是最后的嘲讽。

### 每篇的结构

1. **一个钩子**——开篇就是一个具体场景。但避免"XX 年，在 XX 地，某人在做某件事"的固定句式。钩子的切入方式应多元化：
   - **以问题切入**——"计算机只能算数吗？"（Lisp 可以这样开篇）
   - **以用户痛点切入**——"物理学家不想写代码。"（Fortran 的原始动力）
   - **以历史反讽切入**——"2011 年 Dennis Ritchie 去世，全世界没人注意到——但你的手机、电脑、路由器全在跑他的代码。"
   - **以具体物件切入**——"有一本书，228 页，卖了一百万册。它不教你做大项目，甚至不到两百页。"
   - **以关键时刻切入**——不是笼统的"1954 年"，而是"Fortran 编译器的第一次编译结果出来了——团队紧张地盯着打印纸。"
   - 总之，让每一篇的开头都有自己的性格，不重复同一种句式
2. **核心问题**——这篇语言解决了什么问题？用一句话说清楚
3. **诞生故事**——谁、在什么环境、被什么逼的
4. **关键设计决策**——为什么那么做（而不是别的做法）
5. **遗产**——这条语言留下了什么？解决了当初的问题吗？它意想不到的影响是什么？

### 段落节奏

- **不以机器判断断句**。段落长度由叙事节奏自然决定，不带机械分段感
- **段落宜长不宜短**，参考 DL 系列的段落风格——一段 4-8 句，铺陈时甚至更长，让文字自然流淌
- 紧张处可适当缩短，但一般不要短于 4 句，避免碎段感
- 不要让代码片段打断叙事节奏。需要展示语法时，控制在 3–5 行
- **不要写教程**。不要让读者觉得在看一篇"Fortran 入门"。这不是课程

### 关于代码示例

少量、精准、有冲击力：

```fortran
PROGRAM HELLO
  PRINT *, "Hello, World!"
END PROGRAM HELLO
```

*这是 Fortran 77 的 Hello World。人类第一次可以用接近自然语言的方式和计算机对话。*

不要为了展示代码而展示。只在代码本身就是故事的时刻放代码——比如那句史诗般的 `y = x + 1`。

## 七、图片规范

### 选材原则

这个栏目的图片是最难的——编程语言没有物理形态。策略是：

1. **创造者照片（早期）**——Backus 在 IBM 704 前的留影、Thompson 和 Ritchie 在 PDP-11 前的照片、Eich 在 Netscape 工位上的抓拍。人在工作环境中的照片 > 证件照
2. **时代设备**——IBM 704 的控制台、PDP-11 的正面面板、Apple II 上的 BASIC 界面。硬件本身就是时代的符号
3. **历史性瞬间的屏幕截图**——第一个 Fortran 编译器输出的 punch card、Lisp 1.5 手册的封面、World Wide Web 第一页的代码。这些是软件的"考古照片"
4. **文化符号**——Go 的吉祥物 Gopher、Python 的 logo 演变史、Ruby 的宝石意象。一个语言的文化符号经常比语言本身更有故事
5. **文档封面/手册扫描**——K&R C 的第一版封面、Gang of Four 的设计模式封面。这些书本身是传奇

### 避免什么

- ❌ 纯代码截图（除非是历史性代码段落）
- ❌ 现代的 IDE 界面截图
- ❌ 图表/曲线图
- ❌ 现代语言宣传图

### 来源

- Computer History Museum 在线档案馆
- Bell Labs 历史照片集
- MIT 档案馆
- 各语言创始人的个人网站/博客
- Wikipedia Commons（Historical computing 分类）
- 经典计算机书籍的封面扫描

### 各语言的图片重点

- R：Ross Ihaka 和 Robert Gentleman 在奥克兰大学的早期留影、R 1.0 的发布公告截图、ggplot2 早期绘制的经典图形（"钻石"数据集的可视化）、John Chambers 在 Bell Labs 的照片（S 语言的源头）。R 社区的凝聚力很强，R 会议（useR!）的早期合影也是好素材

### 图文搭配

图片承三种功能：**时代氛围**、**关键实物**、**人物群像**。

**时代氛围图**（如 IBM 704 照片、PDP-11 面板）穿插在叙事段落旁，开篇附近就放一张，让读者第一时间进入历史情境。Fortran 篇的 IBM 704 照片放在首段后，读者读到"25000 个真空管"时能立刻看到实物。

**关键实物图**（如 Fortran punch card、Lisp 1.5 手册封面、K&R C 封面）放在对应技术段落旁，作为叙事节奏的调剂。技术/文化符号如 Python logo 演变、Go Gopher 等也归入此类。

**人物肖像和团队照集中在文末**，设独立章节展示。不在正文中穿插人物肖像——它们在叙事流中起不到太大作用，反而打断节奏。但集中放在篇末时，能营造一种"时代弄潮儿"的群像感——读完故事再看一眼那些面孔，情感浓度更高。每篇至少放 1-3 张人物照，关键团队也可放合影。

### 标注格式

```markdown
![](/images/ritchie-thompson-pdp11.jpg)

```
