```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

*这是 Java 的 Hello World。五行代码，十五个关键词，加上一对花括号、一对圆括号、一个点号、一个分号。和 C 的 `main() { printf("hello, world\n"); }` 比起来，Java 的版本像是在参加一场正装晚宴。你在第一行就感受到了它的性格：正式、安全、绝不省略。*

1995 年 5 月 23 日，旧金山的 SunWorld 大会现场，气氛有些不对。

Marc Andreessen 走上了 Sun Microsystems 的舞台。他是 Netscape 的联合创始人——这个公司过去 12 个月里做的事情让整个业界目瞪口呆：开发了一个叫 Navigator 的浏览器，然后给所有人免费下载，在几个月内席卷了互联网。Andreessen 出现在 Sun 的发布会上本身就意味深长。

"我们有一项宣布。"他对着台下在座的两千多名开发者说。

他停了一下。

"Netscape Navigator——下一个版本——将支持一种新的编程语言。"

台下开始有人交头接耳。什么语言？

"它叫 Java。"

Andreessen 在身后的大屏幕上打开了一个页面——一个普通的 HTML 页面，中间嵌入了一块动态的、活的内容。一个实时股票行情图。价格在变化。数据在网络另一端被更新，然后——"活"在这个浏览器窗口里。

台下安静了两秒钟，然后掌声炸了。

这是人类第一次在浏览器里看到"可执行的内容"。在 1995 年，网页是静态的。你做网页写 HTML，排版文本、放几张图片、做个超链接，差不多就这些了。现在 Netscape 说：我们可以在网页里跑程序了——用 Java 写的程序，直接从服务器下载到你的电脑上运行。

![](/images/ncsa-mosaic-screenshot.png)

*NCSA Mosaic 浏览器，1993 年发布的首款图形化网页浏览器。Gosling 在 1994 年看到 Mosaic 后意识到：Oak 的跨平台设计恰好是为互联网准备的。*

那天晚上，Java 的下载量暴增。到了年底，全世界已经有几十万开发者下载了 Java 的开发工具包。Java 的新闻登上了《纽约时报》、《商业周刊》、《时代》杂志的科技封面。Sun 的市值在几个月内涨了 30 亿美元。

但这个故事有一个巨大的反讽：这门一夜之间成为"互联网语言"的 Java，根本不是为了互联网设计的。它是写给电视机顶盒的。

## 上帝邮件

1990 年 12 月，Sun Microsystems 的工程师 Patrick Naughton 坐在他的工位上，盯着屏幕，情绪降到了冰点。

Naughton 是 Sun 最年轻的前沿技术团队负责人之一，26 岁，聪明、精力充沛、对技术有近乎狂热的信仰。但他受够了。Sun 的 NeWS 窗口系统项目——他被分配的核心工作——正在被内部的官僚主义一点点拖死。Sun 是一家工作站厂商，它的商业模式是卖给企业和工程部门昂贵的 Unix 工作站。公司内部的流程越来越像一个传统大公司——层层审批、无穷无尽的会议、跨团队扯皮。Naughton 觉得他正在浪费生命。

他做了一件很多人会做但很少有人真正去做的事。他写了一封辞职信——但不是普通的辞职信。他直接把邮件发给了 Sun 的 CEO Scott McNealy：

"我要辞职了。但临走之前，让我告诉你一件事。如果我假装是上帝，坐在你的位置上看这家公司——我给你一个建议。现在 Sun 在做的事情是卖更快的硬件给同一群老客户。电脑行业正在发生根本性的变化，消费电子、互动电视、手持设备——这些东西会在五年内改变一切。如果你不从现在开始布局，Sun 会被淘汰。"

Naughton 本可以写好一封标准的"感谢在这家公司的工作经历"然后走人。他没有。他花了整整一个周末写了这封邮件——像他的最后一颗子弹。

McNealy 看了这封邮件。他没有生气。他没有把 Naughton 叫到办公室训话。他说了一句让 Naughton 至今记得的话："你刚才说的那些——你愿不愿意自己去做？"

于是 Naughton 没有辞职。McNealy 给了他一支团队、一笔预算，让他在 Sun 的体制内成立一个"地下组织"——不受大公司流程制约，可以自己决定做什么。1990 年圣诞节前，Naughton 和另外两个人——James Gosling 和 Mike Sheridan——在 Sand Hill Road 2180 号租了一间不起眼的办公室，挂了一个名字叫"Stealth Project"（隐形项目）。

后来改名叫"Green"。

他们的任务是什么？McNealy 给的目标很模糊："看看计算机行业的下一个浪潮在哪里，然后抓住它。"

Naughton、Gosling、Sheridan 的结论是：下一个浪潮是消费电子设备——机顶盒、互动电视、PDA、游戏机。未来的房子不只一台电脑——是每个房间里都有几台小电脑，它们都连着网络，跑着不同厂商的软件，由消费者自己控制。

一台机顶盒的芯片可能是 MIPS 架构的，另一台是 ARM 的，第三台是 x86 的。电视厂商不会为同一种 CPU 架构标准化。Sun 不能像卖工作站那样每家机顶盒厂商发一套编译工具链。

他们需要解决的问题很清楚：**这个编程平台必须在每一种芯片上都能跑，还不要求程序员为每一种芯片重写代码。**

## 虚拟机的种子

1980 年代初，卡内基梅隆大学，James Gosling 在为一个头疼的问题熬夜。

Gosling 1955 年出生在加拿大卡尔加里，高中时就在为卫星数据分析写程序。进入 CMU 读博士之后，他接触到了一件很有意思的东西——UCSD Pascal。UCSD Pascal 是一个"不走寻常路"的 Pascal 编译器：它不把 Pascal 代码编译成特定 CPU 的机器码，而是编译成一种叫 p-code（伪代码）的中间指令。这些 p-code 不是给任何真实的 CPU 执行的——它们给一个叫做"p-machine"（伪机器）的虚拟机执行。这个虚拟机被实现为一个轻量级的软件层，跑在真实的硬件之上。你只要在 VAX 上实现了 p-code 解释器，UCSD Pascal 程序就能在 VAX 上跑；你在 Motorola 68000 上实现了同样的解释器，同一个程序不需要重新编译就能在 68000 上跑。

Gosling 把这个 p-code 虚拟机移植到了 VAX 上，让他导师的程序可以自由地在不同 UNIX 机器之间迁移。多年后他回忆说："我从 CMU 带走的除了博士学位之外，最重要的就是'虚拟机'这个概念。当时它只是一个课上写的作业。但它在我脑子里扎下了。"

1984 年，Gosling 加入 Sun Microsystems，参与了 NeWS 窗口系统的开发。NeWS 本质上是一个基于 PostScript 的显示服务器——它把 PostScript 作为一种"网络可移植的显示指令语言"，让窗口界面可以在网络上传输。这个项目因为内部政治失败了（Sun 内部的另一个团队在推 X Window System），但 Gosling 积累了一个重要的经验：网络上的程序不适合"编死了"的二进制格式——它们应该以一种中间的、可解释的格式在网络上传输，目标机器再把它转成本地代码。

1991 年的那个小办公室里，Gosling、Naughton 和 Sheridan 面对的问题是：用什么语言来写这个面向消费电子的平台？

候选语言很明确——C++。C++ 是当时的主流面向对象语言，Sun 有一批最好的 C++ 工程师，而且 C++ 在性能上接近 C——消费电子硬件的性能有限，每一 Hz 运算能力都很宝贵。

但 C++ 有两个致命问题。

第一，C++ 编译出来的代码是绑定到特定 CPU 架构的。同一个机顶盒的代码，如果在 MIPS CPU 上编译，不能在 ARM CPU 上运行。消费电子行业没有"统一平台"这种东西——不同厂商、不同型号的设备用完全不同的芯片。你不能让开发者为一个机顶盒写一个程序，然后给另一个机顶盒重新编译一次——因为那些设备甚至可能不在同一个操作系统上。

第二，指针。C++ 继承了 C 的全部内存模型——程序员可以直接操作内存地址。这对系统程序员来说是强大的工具，但对消费电子开发者来说是灾难。消费电子设备的软件一旦崩溃，用户不会觉得是"我的操作有问题"——他们觉得那个盒子坏了。C++ 程序中最常见的 bug——空指针、野指针、缓冲区溢出——每一个都足以让一个嵌入式设备死机。

Gosling 确信：C++ 不是答案。

他想起了 CMU 的那个 p-code 虚拟机。他说："我们不要为真实芯片做编译器了。我们做一个虚拟芯片。所有的代码都编译成这个虚拟芯片的指令——字节码。然后针对每一个真实的硬件平台，写一个模拟这个虚拟芯片的'模拟器'。如果 MIPS 平台想要跑 Java，就在 MIPS 上实现这个模拟器——一旦它装好了，所有写好的程序不需要修改就能跑。"

从 C++ 开始改？有人在会议上提过。Gosling 试过——在 C++ 基础上加东西。不到几个星期他就放弃了。C++ 的底层模型太复杂了，你不能在它上面"再盖一层"——它的指针模型、它的多继承、它的运算符重载——每一个特性都会在你试图加入新层时变成隐患。

1991 年 6 月，Gosling 开始从零写一门新的语言。他管它叫 Oak——橡树，因为他办公室窗外就有一棵橡树。

Oak 的设计原则是 Gosling 在那几个月里相当坚定地确立下来的：必须跨平台——通过字节码 + 虚拟机来实现；必须简单——砍掉 C++ 里一切让程序员容易犯错的东西；必须安全——类型系统要严格，内存访问要控制，不能让程序员拿到裸指针。

## 砍掉什么，留下什么

Gosling 做的最重要的决策不是"加了什么"——而是"砍掉了什么"。

他砍掉了指针。Java 没有指针。你可能觉得这是废话——"当然没有，Java 是高级语言嘛"——但在 1991 年，这是极其激进的。C 和 C++ 的整个模型都是建立在对内存地址的直接操作上的。没有指针，你怎么做数组？怎么做链表？怎么做任何动态数据结构？Gosling 的答案是：你不需要指针。数组有索引，对象有引用，内存管理交给垃圾回收器。程序员不需要知道对象在内存的哪个地址。这不仅消除了整个类别的 bug，还让 Java 的安全性从根本上异于 C++——Java 程序不可能写出缓冲区溢出（至少不会"溢出"到别的内存区域）。

他砍掉了多重继承。Gosling 不是没看到 C++ 多继承的初衷——一个类同时是"窗口"和"可滚动"的，多好——但他也看到了 C++ 社区被菱形继承折磨得生不如死的十年。Java 用"接口"（interface）替代了多继承。接口只声明方法签名，不提供实现。一个类可以"实现"多个接口，这意味着它承诺遵守多个行为规范，但实现的继承冲突永远不会出现——因为冲突全被限制在接口层面，不会传导到实现。

他砍掉了运算符重载。在 C++ 里你可以让 `+` 运算符做任何事情——两个矩阵相加是合理的，两个数据库连接"相加"是什么？Gosling 的立场是：运算符重载在商业软件实践中造成的混乱比它解决的问题多。Java 里 `+` 只对数字和字符串有意义。你要是想给两个对象做运算，用 `add()` 方法。清清楚楚。

他加入了垃圾回收。这不是 Gosling 的原创——Lisp 在 1958 年就有了垃圾回收，Smalltalk 在 1970 年代也有了。但在系统编程社区里，垃圾回收一直被认为是"太慢"、"不靠谱"、"真正的程序员不需要"的东西。Gosling 不这么看。他说："真正的程序员也是人。人在手动管理内存时一定会犯错。"垃圾回收在当时的主流系统编程语言中几乎是禁忌——但 Java 选了这个方向。

这些决策放在 2026 年回头看，每一条都像是常识。但在 1991 年，每一条都是对 C++ 社区的正面挑战。Gosling 不是在做一个"更好的 C++"，他是在做一个"完全不一样的 C++"——一个在"信任程序员"和"保护程序员"之间选择了后者的语言。

## Star7：给一个不存在的世界

1992 年 9 月 3 日，Green 团队首次向 Sun 的高层演示了他们的成果。

他们给它取名叫 Star7（\*7）。一台手持设备——比当时的 PDA（比如 Apple Newton）小一圈——带有 5 英寸彩色 LCD 触摸屏。这在 1992 年看起来像从未来世界掉下来的东西。大多数掌上设备是黑白的。触摸屏更是实验室科技。

Star7 运行着一个完整的操作系统——一个用 Oak 语言写的、带图形界面的操作系统。

![](/images/star7-prototype-device.jpg)

*Star7（\*7）原型机，1992 年。5 英寸彩色触摸屏、无线网络、基于 Oak 语言的完整图形操作系统。这台手持设备在 1992 年看起来像是从 2022 年穿越回去的。但消费电子厂商的反应是"太先进了，我们还没想做这种东西"。*

屏幕上有一个叫 Duke 的动画角色——一个小小的人物，会在角落里做各种表情，当用户操作界面时它会给出反应。Duke 是团队里的设计师 Joe Palrang 画的——他后来成了 Java 社区的标志性吉祥物。

![](/images/duke-java-mascot-original.jpg)

*Duke，原 Oak 系统上的智能代理角色，后来成为 Java 社区的标志性吉祥物。最初设计为 Star7 界面中的动画助手，挥手姿态是其经典形象。*

Star7 能做很多事情：电视节目指南、万能遥控器、分布式白板（多个设备之间可以互发"活动对象"）。它是用 Oak 写的、跑在一个虚拟机上的、完全图形化的个人数字助理——在 1992 年，这是一个革命性的产品。

问题是——消费电子厂商不想要它。

Sun 带着 Star7 跑去日本，展示给几家电视机厂和机顶盒公司。这些厂商的反应惊人地一致："这个太先进了。我们还没想到要做这种东西。"1992 年的消费电子行业还没有想好怎么应对数字化。大多数机顶盒只做一件事——接收有线电视信号，调个频道。你跟他们说"你可以在机顶盒上跑程序，甚至让它变成一个双向交互设备"——他们会礼貌地点头，然后回去继续做他们的模拟电视芯片。

1993 年，Green 项目改名为"FirstPerson"（第一人称），试图找到它的实际用户。团队测试了互动电视、视频点播、游戏机——每一个方向都碰壁。到了 1994 年初，项目濒临死亡。

Gosling 后来这样回忆那段时间："我们造了一扇非常棒的门。问题是——没有墙需要它。"

## 橡树遇见互联网

1994 年春天，Gosling 参加了一个技术会议。回来之后，有同事跟他说："你有没有看过一个叫 World Wide Web 的东西？"

Gosling 打开了一个浏览器——NCSA Mosaic。他在屏幕上看到了一个页面，上面有文字、图片、链接。你点一个链接，它从地球另一端的某台服务器上取来另一个页面，显示在你面前。

他盯着屏幕看了好几分钟。

"这不是超链接的问题。"Gosling 后来回忆当时的反应，"我看到的不是一个浏览器。我看到的是一个巨大的、分布式的、充满异构设备的网络。这个网络上每一种机器的操作系统都不同——Windows、Mac、Unix——没有一个能统一。而这个网络需要一种共同的语言。"

Oak 的问题突然有了答案。

Oak 不是为了互联网设计的。但 Oak 设计时对跨平台、安全性、稳定性的要求——这些恰好是互联网最缺的东西。你在服务器上写一个程序，你不知道用户用的是 Windows、Mac 还是 Unix 工作站。你不想为他们每一个平台分别维护一个编译版本。你要的是一个可以在浏览器里运行的程序——一个"applet"——当用户打开网页时，它自动从服务器下载到本地运行。

Gosling 用 Oak 写了一个浏览器。他管它叫 WebRunner（网络奔跑者）——后来改名叫 HotJava。HotJava 能理解 HTML 页面中嵌入的一个特殊标签——`<APPLET>`。当浏览器解析到 `<APPLET>` 标签时，它会从一个指定的 URL 下载一段字节码，然后在 HotJava 内置的 Oak 虚拟机中执行它。

在 1994 年，这看起来像魔法。一个在互联网上随意传输的二进制数据块，能在不知名的客户端机器上安全地运行。

Gosling 把 HotJava 演示给 Sun 的高层看。高层的反应平淡得令人沮丧："互联网？那个大学里传论文的东西？"

Gosling 和 Naughton 做了所有人都意料之中的下一步：他们自己动手。他们给 Sun 的 Web 服务器加了一个临时页面，放上了 HotJava 的二进制下载包。然后 Gosling 给他在 Sun 内部认识的一个关键人物发了邮件——那个人认识 Netscape 的 Marc Andreessen。

Andreessen 拿到了 HotJava 的拷贝。他当时正在为浏览器寻找"可扩展性的下一步"——HTML 在变得复杂，但网页仍然是静态的。Andreessen 意识到：如果浏览器能运行程序，那它就从一个"文档阅读器"变成了一个"应用平台"。

Andreessen 当天就给 Gosling 打了电话。

"你的语言什么时候能放到网上？"

## 从 Oak 到 Java

在走向市场之前，有一个法务问题必须解决。橡树。

"Oak"这个商标已经被一家叫 Oak Technology 的公司注册了——这家公司做 CD-ROM 控制器，在准备起诉任何人。Sun 的法律部门说：不能叫 Oak，会输掉诉讼。

Sun 的营销团队组织了几轮头脑风暴。候选名字包括：Dynamo、WebDancer、Silk、Jolt、DNA、TIO（"This Is Object-oriented"的缩写）。都不对。

在某次头脑风暴会议上，有一个名字被随口提了出来——"Java"。印度尼西亚爪哇岛出产的咖啡，程序员喝的那种。有人注意到这个单词的气质：它不是一本正经的（不像"OOP Language v2.0"），它有些轻松、有些酷、像几个人在咖啡馆聊天时随口起的名字。

Gosling 后来笑着说："我们选 Java 主要是因为它在头脑风暴的时候——点它的时候感觉最放松。"

1995 年 1 月，Sun 做了一次关键决策。McNealy 拍板：正式把 Oak 改名 Java，投入数百万美元做市场推广。Duke 从 Star7 的智能代理变成了新的吉祥物。Sun 打出了一个后来被全世界记住的口号——"Write Once, Run Anywhere"（一次编写，到处运行）。

Oak 的规范文档中的所有"Oak"被替换成了"Java"。T 恤、马克杯、海报——全印上了那个咖啡热气腾腾的 logo。

![](/images/java-coffee-cup-logo-original.svg)

*Java 咖啡杯 logo，1995 年。这个充满生活气息的标志在技术圈里独树一帜——它暗示了一种轻松感：一杯咖啡、一行代码、一个正在运行的世界。*

![](/images/green-team-bbq-1997.jpg)

*Green 团队 1997 年的重聚合影。五年前他们在 Sand Hill Road 的小办公室里创造了一门为机顶盒设计的语言——五年后那门语言正在统治互联网。前排左起：Al Frazier、Joe Palrang、Mike Sheridan、Ed Frank、Don Jackson、Faye Baxter、Patrick Naughton、Chris Warth、James Gosling、Bob Weisblatt、David Lavallee、Jon Payne。*

## 征服世界的 90 天

1995 年 5 月到 8 月，Java 经历了互联网历史上最疯狂的一次技术爆发。

5 月 23 日 SunWorld 之后，Sun 的 Web 服务器几乎被下载请求压垮。Java Developer's Kit（JDK）的 alpha 版本——一个连安装程序都没有的 zip 压缩包——被下载了成千上万次。开发者们解压到自己的 Unix 工作站上，用命令行编译第一个 Java 程序。报纸和杂志开始报道这种"能在浏览器里跑的程序"。《纽约时报》的科技记者 John Markoff 发表了一篇长文，标题是《为什么 Sun 认为 Java 是下一个大事》。

7 月，Sun 免费发布了 JDK 的早期 beta 版本。全球各地的程序员蜂拥而至。8 月，Netscape 在 Navigator 2.0 beta 中正式加入了对 Java applet 的支持。到 1995 年底，Java 的下载量超过了任何软件在历史上同期的记录——几十万份。对于一个被定义为"机顶盒编程语言"、在一年前还濒临死亡的项目，这是一个让人眩晕的转折。

1996 年 1 月 23 日，JDK 1.0 正式发布。严格意义上 1.0.2 才是第一个稳定版本，但 JDK 1.0 定义了什么是"Java 标准库"：AWT（Abstract Window Toolkit）——一个笨重但可用的图形界面系统；`java.lang` 和 `java.util`——核心语言和工具包；`java.applet`——让浏览器嵌入运行的小程序框架；`java.net`——网络 I/O；`java.io`——文件和数据流 I/O。

这个版本在今天看起来极为简陋——没有泛型、没有集合类（除了一两个基本容器）、没有现在 Java 程序员觉得理所当然的几乎所有东西。但在当时，它已经足够让全世界的开发者兴奋到疯狂。

1996 年 5 月，Sun 创立了 JavaOne 大会。第一届就有 6000 人参会——在会场里，穿着 Java T 恤的程序员挤满了走廊。

Java 成了 1990 年代后期最受关注的编程语言。

## 真正重要的东西

回看 Gosling 的设计，最被低估的创新不是语言本身——是它背后的那个虚拟机。

JVM（Java Virtual Machine）的设计在整个计算机史上有着独特的地位。它不是一个"在真实操作系统上运行的仿真层"——它是一套精心定义的指令集规范，一套字节码标准。Java 编译器把源代码编译成 `.class` 文件，文件中是 JVM 的指令序列（字节码）。任何实现了 JVM 规范的平台——无论它用的是哪种 CPU、哪种操作系统——都能解释执行这些字节码。

![](/images/jvm-architecture.svg)

*JVM 架构图。ClassLoader 加载字节码，执行引擎（含 JIT 编译器）将其转换为本地机器码，运行时数据区包含方法区、堆、栈等关键区域。这一架构让 "Write Once, Run Anywhere" 成为可能。*

这个理念本身不是全新的。UCSD Pascal 的 p-code 在 1970 年代末就做过类似的事。但 Gosling 把这件事做到了工业级。JVM 的字节码指令集是精心剪裁的，它不需要真实 CPU 的那些古怪的历史遗留设计。它的大小和复杂度都控制在一个合理的范围内——JVM 在 1990 年代中期就可以塞进一个几兆的浏览器插件里。

第一个 JVM 实现是一个字节码解释器——性能确实不如本地编译的 C++。但真正改变 JVM 命运的技术出现了：JIT（Just-In-Time）编译。1996 年晚些时候，Sun 和一些第三方开发商开始在 JVM 中集成 JIT 编译器。当一个方法被反复调用时，JIT 编译器会把它从字节码编译成本地机器码——然后直接执行本地码。同样的 Java 程序，第一次跑很慢，跑几秒钟之后越来越快——因为热代码路径全被编译成了本地码。到了 2000 年代 HotSpot JVM 出现之后，Java 在某些场景下的性能已经接近甚至达到 C++ 的水平。

JIT 编译让 Java 第一次真正可以用于高性能的后端应用。一个 1995 年被嘲讽为"跑起来像在糖浆里游泳"的解释型语言，到了 2000 年代末已经能和原生编译的 C++ 在服务器端平起平坐。

但 JVM 的贡献远不止性能。它是一个"语言无关的运行时"。字节码规范是一个中立的平台——理论上，任何语言的编译器都可以生成 JVM 字节码。Scala、Kotlin、Groovy、Clojure——这些语言在 2000 年代和 2010 年代先后选择跑在 JVM 上。它们不需要重新实现线程模型、不需要重新实现垃圾回收、不需要重新实现一套标准库——JVM 提供了这一切。

Java 原本只是"第一个在 JVM 上跑的语言"。它后来变成了"JVM 生态中最重要的语言"。但 JVM 本身成了比 Java 更持久、更广泛的遗产。

## 企业级的征服

1998 年，Sun 发布了 J2SE 1.2（Java 2 Standard Edition），以及更重要的——J2EE（Java 2 Enterprise Edition）。Java 正式向企业级服务器市场发起总攻。

J2EE 定义了一套架构标准：Servlet（处理 HTTP 请求的 Java 程序）、JSP（Java Server Pages——在 HTML 中嵌入 Java 代码）、EJB（Enterprise Java Beans——企业级业务组件）、JDBC（Java 数据库连接）。这些技术让 Java 成为了企业级后端开发的标配。银行、保险、电信、航空公司、电商——所有需要高可靠性的系统，Java 成了首选。

不是因为它最优雅。Java 在企业级市场的胜利不是因为它的设计有多么超前——而是因为它最稳定、最可维护、对旧代码最友好。Java 的向后兼容性是它的宗教。你 1998 年写的 JDK 1.1 的代码，在 2026 年的 Java 26 上几乎不需要修改就能编译。在软件行业，这是近乎偏执的承诺——但企业用户爱死它了。对一个银行的 CIO 来说，没有任何事情比"我五年前写的交易系统在新版本上还能运行"更让人安心。

Apache Tomcat（1999）、JBoss（1999）、Spring（2002）——这些开源框架把 Java 从一门语言变成了一个工业体系。Spring 尤其改变了游戏规则：它引入的依赖注入、控制反转、面向切面编程——这些概念后来被几乎所有主流框架借用。Spring 的作者 Rod Johnson 在 2002 年写了一本书《Expert One-on-One J2EE Design and Development》，在里面展示了一个比官方 EJB 方案简洁得多的框架。这本书后来成为了 Spring 项目的基础。Java 社区的力量在于：当语言本身进化缓慢时，社区可以用开源框架来填补空白。

2008 年，Google 发布了 Android——一个用 Java 语法做开发语言的移动操作系统。严格来说，Android 不用标准 JVM——它用自己的 Dalvik 虚拟机（后来被 ART 替代）——但 Java 开发者几乎可以无缝迁移过来。Java 在移动端迎来了第二次生命。到 2010 年代末，全球有超过 25 亿台 Android 设备在运行——每一台上跑的 App，大多数用 Java 编写。

## 无心插柳的征服

Java 的故事里最核心的那个反讽一直没有消失过：它为一台没人想买的设备（机顶盒）设计，最后统治了所有人都想要的互联网。

这个反讽背后藏着一个更深刻的规律。最成功的平台往往不是为它们最终的市场设计的。SQL 的原型是为通用数据查询做的，World Wide Web 的原型是为粒子物理学家共享论文做的。Java 的原型是为交互电视做的。这些技术之所以能跨跃初始市场，是因为它们在设计时解决的是"普遍性的问题"——而不是某个特定领域的问题。

Java 在 1990 年到 1994 年之间那些"做了一堆没人要的东西"的四年，恰恰是它磨炼这些普遍性能力的四年。跨平台？机顶盒行业有几十种不同的 CPU。安全？机顶盒崩溃了用户会骂厂商。稳定？机顶盒不能频繁重启。这些要求在消费电子行业显得过于苛刻——但在互联网时代，它们变成了最基本的需求。

这四年里 Gosling 做出的那些"砍掉的东西"——砍指针、砍多重继承、砍运算符重载——每一个都有可能毁掉 Java 在当时的战场上的竞争力（因为 C++ 程序员会嘲笑它们的缺失）。但到了互联网时代，每一个缺失都变成了优势。没有指针，意味着 applet 不会因为野指针而让用户的浏览器崩溃。没有多继承，意味着从服务器下载的陌生代码不会在复杂的继承关系中制造歧义。垃圾回收，意味着开发者不需要关心内存释放——在 Web 开发中，成千上万个不同的程序片段在同一个浏览器窗口里共享内存，手动管理几乎是不可能的。

Java 在 2020 年代的份额在被侵蚀——Python 在数据科学和 AI 领域取得了统治地位，Go 在云原生基础设施方面更高效，Kotlin 在 Android 开发上比 Java 更现代。但 Java 仍然是全球部署量最大的语言之一。2026 年的今天，数十亿台设备——从企业级服务器到银行 ATM 机到智能电视——在运行 Java 代码。它的 JVM 生态、企业级开发的范式、架构中立（architecture-neutral）的理念，已经融入每一个现代程序员的 DNA。

Java 选了一条路：用虚拟机换安全，用性能换开发效率，用严格换可维护性。这条路的代价是 Java 永远没有 C++ 的极致性能，永远没有 Python 的极简表达，永远没有 JavaScript 的灵活动态。但它的回报是：Java 成为了一门"大型组织里的普通工程师也能写出不崩溃的系统"的语言。

1990 年 Patrick Naughton 写那封邮件的时候，他想要的是一个能让他重新爱上编程的挑战。Gosling 想要的是一个能解决跨平台问题的架构。McNealy 想要的是 Sun 在下一个时代找到生态位。没有一个人——包括 Andreessen 那个宣布之后的掌声——能料到这门 1991 年为了机顶盒而造的语言，会改变计算世界的面貌。

1996 年，Java 的营销团队在展台上放了一大张世界地图，上面插满了各种颜色的图钉。每个图钉代表一个"Java 在运行"的地点。到展会结束的时候，地图上几乎找不到空白处。

口号写在展台的正上方：Write Once, Run Anywhere。

它不是完全真实的。跨平台的承诺在早期被嘲讽为"Write Once, Debug Everywhere"——不同平台上的 JVM 实现总有细微差异。但 Java 做到了足够接近这个理想。在这个意义上，Java 不是"一次编写到处运行"——它是"一个人写了一个虚拟芯片，然后整个行业都接受了这个虚拟芯片。"

这才是虚拟机真正的征服。

## 人物

![](/images/james-gosling-sun-microsystems.jpg)

*James Gosling（1955–），Java 的创造者。加拿大卡尔加里人，卡内基梅隆大学博士，在 CMU 期间写了 Gosling Emacs 和第一个 p-code 虚拟机。1984 年加入 Sun，1990 年加入 Green 项目，创造了 Oak/Java。他是语言设计师中少数几个自己写编译器、写虚拟机、写标准库的"全栈语言创造者"。2010 年 Oracle 收购 Sun 后离职，先后加入 Google、Liquid Robotics、Amazon Web Services，2024 年退休。*

*Patrick Naughton（1965–），Green 项目的发起人。1990 年 12 月写给 Sun CEO Scott McNealy 的"上帝邮件"直接催生了 Green 项目。他的核心信念是"消费电子 + 网络将改变一切"——这个信念在 Star7 的原型上没有变现，但在互联网时代以十倍的速度兑现了。（注：Naughton 的个人肖像在开放档案中暂未找到，参见正文 Green 团队合影中前排右起第二位。）*
