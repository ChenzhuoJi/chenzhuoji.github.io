```php
<?php echo "Hello, World!"; ?>
```

*这是 PHP 的 Hello World。你注意到的第一件事是什么？不是语法里的 `echo`，不是分号——是那个 `<?php`。它告诉你：我正在切入 HTML。PHP 不像其他语言那样"输出 HTML"——它在 HTML 中开一扇窗。这个区别就是 PHP 的全部秘密。*

1995 年 6 月 8 日，Rasmus Lerdorf 在 Usenet 的 `comp.infosystems.www.authoring.cgi` 新闻组里发了一封邮件。标题很普通——"Announce: Personal Home Page Tools (PHP Tools) version 1.0"——内容更像是一份自述，而不是一个改变互联网的宣言。他用朴素的技术写手口吻写道：这是一个给个人主页用的工具集，它能帮你跟踪谁访问了你的页面，能把表单数据嵌入你的 HTML，还支持一些简单的数据库查询。"你不需要 root 权限。你不需要 Perl 或 Tcl。你不需要访问 httpd 日志文件。"

这封邮件的每一行都在做同一件事：消除障碍。"你不需要"——今天你读出这个词的时候，可能不会觉得它有什么力量。但在 1995 年，"你不需要"是一个革命性的承诺。因为在 1995 年，做一个动态网站需要的东西太多了。

## CGI 的暴政

当你试图理解 PHP 为什么存在的时候，你必须先理解 CGI——Common Gateway Interface——以及它让普通人的生活有多痛苦。

1995 年的互联网是一个以静态 HTML 文件为主的世界。你写好一个 `.html` 文件，把它扔到服务器的某个目录里，全世界就能看到它。但如果你想做一个"动态"的东西——比如一个留言板、一个访客计数器、一个用户登录页面——你就必须进入另一个维度。你需要理解 HTTP 请求的生命周期，需要理解服务器的进程模型，需要在 `cgi-bin` 目录下放置一个可执行脚本，需要理解环境变量（`QUERY_STRING`、`PATH_INFO`、`HTTP_USER_AGENT`——这些东西你不会在任何教程里自然学到），需要理解文件权限（`chmod 755`——为什么是可执行？CGI 脚本不是 HTML 文件，它是一个独立的进程），需要理解 Perl 或者 C 或者 Shell 脚本，需要理解数据库连接并且祈祷你的共享主机允许它。你每往前走一步，都可能踩到一个看不见的地雷。环境变量拼写错了——页面空白。文件权限错了——500 Internal Server Error。数据库连不上——页面空白。你甚至找不到错误日志在哪——共享主机管理员不会给你 shell 访问权限的。

而且 CGI 在技术上有一个根本性的缺陷：它为每一个 HTTP 请求创建一个独立的进程。当有人访问你的留言板时，Web 服务器 fork 出一个新进程，加载 Perl 解释器，解析你的脚本，执行它，输出结果，然后销毁整个进程。如果同时有 100 个人访问你的留言板，服务器上就瞬间多了 100 个进程在打架。这就像你去一个餐厅，每点一杯饮料厨房就专门给你烧一壶水——不管你要的是一杯茶还是一杯白开水。

这个架构意味着 CGI 是"能跑，但经不起任何规模"的。一个只有几个人访问的个人网站还好，一个开始有几十个访问者的论坛——你的共享主机管理员很快就会收到投诉，然后你的账号被关停。

那么有没有更好的办法？有。你可以用 SSI（Server Side Includes）——在 HTML 里嵌入 `<!--#include virtual="/header.html" -->`，让服务器在发送页面之前把它拼接起来。但 SSI 只能做简单的文件包含，做不了数据库查询。你可以用 Netscape 的服务器端 JavaScript（LiveWire）——但那是 Netscape 自家的商用服务器，不是每个共享主机都有。你还可以用 Java——1995 年 Java 刚刚随 HotJava 浏览器发布，Applet 的概念让人兴奋，但你要写一个完整的 Java 程序然后嵌入到网页里——对普通人来说就像让一个刚学会骑自行车的人去开飞机。

所以 1995 年的大局面是这样的：如果你想做一个动态网站，你的选择几乎只有 Perl/CGI。那是唯一一条从"个人主页"通往"动态网站"的路。而那条路上挤满了 fork 出来的进程、借来的环境变量、神秘的权限错误和一句接一句的 `500 Internal Server Error`。

Rasmus Lerdorf 不是计算机科学家，不是语言设计者，甚至不是一个在学术机构上班的研究员。他是一个来自格陵兰的工程师，1993 年刚从滑铁卢大学的系统工程系毕业，在加拿大做一份普通的技术工作。他遇到的问题是：他想在自己的个人主页上放一个访客计数器，了解谁在访问他的页面，"看看是自己的朋友还是陌生人"——就这么简单的一件事。他不想学完整个 Perl，不想理解 Apache 的模块开发接口，不想 fork 一个进程来统计一次页面访问。他只想在自己的 HTML 页面里加一行代码，就能记录访问者的 IP 地址、浏览器信息和访问时间。

于是他做了一个叫 PHP Tools 的东西。

## 格陵兰来的工程师

Rasmus Lerdorf 1968 年出生在格陵兰西海岸的迪斯科岛（Qeqertarsuaq），一个在地图上几乎找不到的北极小镇。格陵兰当时是丹麦的殖民地，他的父亲在那边做工程师。他最早的记忆里包括北极的极昼和极夜——夏天太阳不落，冬天太阳不起。他的第一台计算机是中学时接触的 Commodore VIC-20——他用磁带加载程序，用 BASIC 写了一点算算数的小程序。1980 年全家移居加拿大，1983 年到多伦多北边的 King City。高中毕业后他进了滑铁卢大学，读系统工程——一个混杂了计算机、电子工程和优化的古怪专业。

他不是一个"编程天才"的典型画像。他不是在大学宿舍里写了一个操作系统内核才去睡觉的那种人。滑铁卢的系统工程让他学会了如何把问题分解成可以管理的模块——不是数学上的优雅分解，而是工程上的实用分解。"我完全不知道怎么设计和实现一门编程语言，"他后来接受采访时说，这句话不是谦虚。"我完全不知道怎么设计和实现一门编程语言。我只是不断地加下一个合理的功能。"

1993 年，他在为卡尔加里大学做一份工作的时候，用 C 语言写了一些 CGI 程序来处理他的个人主页。"我住在加拿大，但在世界各地都有朋友。我想让他们知道我做了什么，也想看看谁在关心我的生活。"他的第一个"工具"是一个简单到几乎有点傻的功能：在页面上放一个计数器，每次有人访问就加一。然后他加了一个表单处理功能——朋友给他发了一封网页留言，他能在服务器上收到。"当时 Perl 是 CGI 的标准语言，但我觉得 Perl 太烦人了，我只想快速解决自己的问题。"他写了一段 C 代码来解析表单输入——不是因为他想写一个语言的运行时，而是因为他手头最熟悉的语言就是 C。

1994 年，他的工具集有了名字：Personal Home Page Tools，简称 PHP Tools。

## 那封邮件

1995 年 6 月 8 日，Lerdorf 在 Usenet 上发布了 PHP Tools 1.0。邮件全文可以在 Google Groups 里找到——它保存了 Usenet 的一个时间胶囊。

他这样写道：

> **Announce: Personal Home Page Tools (PHP Tools) version 1.0**
> 
> 我在这里发布一个我开发的一套工具，用于创建和管理个人主页。
> 
> 它包括但不限于：
> - 跟踪你页面上访客的日志
> - 在你的页面上显示你页面的访问统计
> - 在你的页面上集成表单
> - 在 PHP 中包含对 mSQL 数据库的支持
> 
> 你不需要 root 权限。你不需要 Perl 或 Tcl。你不需要访问 httpd 日志文件。这些工具是用 C 写的，以 CGI 二进制文件的形式运行。我已经在一些站点上测试过，它运行得很好。如果你遇到了任何问题，请告诉我。

然后他加了一句很重要的话——"This is free." 如果你今天读这封邮件，你可能会觉得它太简单了。这不是技术革命的语言——没有"新的计算范式"，没有"打破界限的设计哲学"，甚至没有"请把你的意见反馈给我"。它就是一个工程师在 Usenet 上贴了一个自己觉得有用的工具。

但如果你仔细读，你会发现 PHP 的基因密码已经在这封邮件里写好了：**消除依赖**。你说你不需要 root 权限——这是对共享主机用户的承诺，他们只有 FTP 上传的权力。你说你不需要 Perl——这是对非程序员的承诺，他们不想再学一门语言才能做一个小功能。你说你不需要访问 httpd 日志文件——这是对没有 shell 访问权限的人的承诺，你不需要去服务器的 `/var/log` 目录下翻找什么。这封邮件的每一行，都对应着一个让普通人做不了动态网站的门槛。

我们今天看来，觉得做网站是一件简单的事情：买个域名，租个服务器，装个 WordPress，十分钟就能上线一个带数据库的、有用户系统的、能发文章的、带评论功能的网站。但在 1995 年，"做一个动态网站"这件事的门槛高到几乎只有系统管理员和 Perl 程序员能做。Lerdorf 的 PHP Tools 第一次把这个门槛降到了"只要你有 FTP"。

邮件的回复数量不多——Usenet 在 1995 年已经有近百万用户，但真正关注 CGI 开发的人不多。回复的有几个人说"不错，正是我需要的"，有一个人报了一个 bug，有一个人问能不能支持别的数据库。没有欢呼，没有掌声，没有风投机构发邮件问他要不要融资。就是一个工程师在一个角落发了一个通知，然后继续干自己的事。

但有人开始用它了。

## "我不知道怎么让它停下来"

PHP Tools 的发布没有引起轰动，但它在一个很小的圈子里传播开了。原因是它的确解决了一个真实的问题——而且解决得非常"低门槛"。

当时的 PHP 语法不像今天我们熟知的 PHP。最初版本的 PHP 使用类似 SSI 的标签风格：

```php
<!--include /text/header.html-->
<!--getenv HTTP_USER_AGENT-->
<!--if substr $exec_result Mozilla-->
  Hey, you are using Netscape!<p>
<!--endif-->
```

看到这个语法你会觉得奇怪——这怎么像 HTML 注释？对，它就是 HTML 注释。当 PHP 解析器遇到 `<!--`，它就切换到 PHP 模式；遇到 `-->`，它就切回 HTML 模式。这意味着即使用户的浏览器不支持 PHP（当时的大部分浏览器确实不支持），页面也不会出错——浏览器会把这些块当作注释直接忽略。这个"降级友好"的设计在今天看来有种笨拙的体贴：如果你的服务器不支持 PHP？没事，页面还能看，只是动态内容不显示了。

1995 年到 1997 年是 PHP 的"有机生长"阶段。Lerdorf 不断收到用户的邮件，说"能不能加这个功能"、"能不能支持那种数据库"。他就像一个餐馆老板被顾客点菜一样，一开始他只想卖一碗面，但顾客说能不能再加个蛋，然后说能不能加个卤蛋。最后他的菜单越来越大。"我从没想过它会长成现在这样，"他后来说，"我一开始只是想记录谁访问了我的页面，结果人们开始用它做整个网站。"

1996 年，PHP/FI 2.0 发布了——FI 代表 Forms Interpreter。这个版本标志着 PHP 从"一组个人主页工具"变成了"一种可以独立工作的脚本解释器"。它已经有了变量（`$foo`）、数组、字符串处理、对多种数据库的支持（mSQL、MySQL、PostgreSQL）。它的语法从 HTML 注释风格转变成了更像 Perl 的风格——也就是我们今天看到的样子，`<?php ?>` 标签加上分号结尾的语句。

但 PHP 的代码质量是"拼凑"出来的。Lerdorf 自己承认：有些函数的名字来自它底层调用的 C 库——`strpos` 的名字直接来自 C 的 `strpos`，`str_replace` 也是从 C 抄来的。有些函数的参数顺序不一致——`array_filter` 的第一个参数是数组，第二个是回调；而 `array_map` 的第一个参数是回调，第二个是数组。为什么？因为 Lerdorf 在写这些函数的时候没有统一的规范——"我写了函数 A 的时候觉得回调在前好，写了函数 B 的时候觉得数组在前好——它们不是同一时刻写的，我不记得我当时怎么想的了。"在 PHP 的早期版本里，函数名的长度甚至被用作哈希函数——也就是说，函数名的长度影响程序在内部的查找效率，所以有些函数名被故意取成特定的长度来优化哈希分布。这不是设计，这是妥协。

但恰恰是这种"非设计"让 PHP 变得极其务实。Lerdorf 不会为了语言的形式美去重构接口——如果有人写信说"我想在模板里用这个功能"，他下个版本就加上。PHP 没有等待一个计算机科学家坐下来画架构图——它是被用户需求推着往前走的。用户说要做电子商务，它加 session 管理。用户说要做论坛，它加强了对 MySQL 的深度支持。用户说代码太混乱了，它逐渐完善了函数库。

这桩故事里最有趣的反讽是：PHP 不是"设计"出来的，它是"长"出来的——而恰恰是这种"长出来"的性质让它成了最适合普通人的语言。一门精心设计的语言（比如 Java、C#）有严格的类型系统、规范的命名管线、优雅的继承层次——但你得先成为一个合格的程序员才能用它们。PHP 没有这些——它乱，它无组织，它令人沮丧地不一致——但你打开一个 HTML 文件，塞进 `<?php echo "Hello"; ?>`，在共享主机上解压，它就工作了。不需要入口类，不需要 `public static void main`，不需要理解编译和解释的区别。

## 两名以色列学生

1997 年，PHP 的发展轨迹被两个以色列理工大学的学生改写了。

Andi Gutmans 和 Zeev Suraski 当时在做一个电子商务项目。他们需要一个能在 Web 服务器上运行脚本的语言，PHP/FI 是当时最接近他们需求的选择。但很快他们发现 PHP/FI 的解析器有一些根本性的局限——它不能处理他们需要的复杂表达式，它的性能在大型应用上不够好。"我们花了大量时间试图改进 PHP/FI 的解析器，最后我们发现最好的方法是从头写一个，"Zeev Suraski 在后来的一次技术演讲中回忆道，"我们没有告诉 Rasmus，我们先做了一个原型。"

Andi 比他的 25 岁看上去更年轻，带着理工学院学生特有的那种"我相信我能造一个更好的"的自信。他们用 C 重写了 PHP 的解析器——全新的词法分析器、全新的语法分析器、全新的解释器核心。然后把代码发给了远在加拿大的 Lerdorf。

Lerdorf 收到代码的时候是什么心情？他后来在多个场合描述过这一刻："我意识到这两个家伙比我聪明多了。他们做的引擎比我做的好得多。"这句话不是自嘲——Lerdorf 是系统工程出身，他对语言解析器、编译原理、虚拟机的设计并没有深入的研究。Andi 和 Zeev 是计算机科学背景，他们更理解如何设计一个可扩展、高性能的脚本引擎。

1997 年底，三人达成协议：Andi 和 Zeev 的引擎将成为 PHP 3 的基础。名字也从 "Personal Home Page" 改成了递归缩写 "PHP: Hypertext Preprocessor"——"PHP" 本身成了缩写的一部分。这个改变有象征意义：PHP 不再是"个人主页工具"，它是一门正经的编程语言。

1998 年 6 月，PHP 3.0 正式发布。它的核心就是 Andi 和 Zeev 重写的引擎——后来他们给它起了个名字叫 Zend Engine。"Zend" 是 Zeev + Andi 的名字组合，和 "Zen"（禅）的发音接近——"一种宁静、简单的智慧"，Zeev 后来说。

Zend Engine 让 PHP 第一次有了一个"专业"的核心。它的架构是传统而有效的：编译阶段把 PHP 源码翻译成 opcodes（操作码），执行阶段在 Zend Virtual Machine 上运行这些 opcodes。这听起来像 Java 的 JVM，但实际上它简单得多——没有 JIT 编译，没有高级优化，只是一个直接的 opcode 解释器。但它足够快，足够稳定，而且——最重要的是——它为后来的 PHP 4 到 PHP 8 提供了一个持续改进的基础。

1999 年，Andi 和 Zeev 在以色列的 Ramat Gan 创立了 Zend Technologies。这标志着 PHP 从一个人的副业变成了一家公司的核心业务。Lerdorf 没有加入 Zend——他继续在技术路线上保持独立的贡献者身份。"我从来没想过要开一家公司，"他说。"我写代码是因为我想解决自己的问题。有人觉得这个解决方案有用，那很好。但我不适合管理团队。"

Andi Gutmans 和 Zeev Suraski 的故事在开源世界里是一个罕见的例子：两个用户不满现状，直接重写了核心代码，然后原作者说"你们做得比我好，我退后一步"。没有爆发社区分裂（像后来 Node.js 分裂成 io.js），没有漫长的政治斗争，没有创始人占有欲作祟。"Rasmus 是我见过的最没有 ego 的创始人，"Andi 在多年后的一次采访中说道。"他看了我们的代码，说'这比我做的好多了'，然后就放手了。这种品质极少有人拥有。"

2000 年 5 月 22 日，PHP 4.0 发布，使用 Zend Engine 1.0。PHP 4 引入了超级全局变量（`$_GET`、`$_POST`、`$_SESSION`），从此你不用再担心哪个变量来自哪个作用域；引入了更多的缓存和性能优化；支持了更多的 Web 服务器（不仅仅是 Apache）。PHP 4 让 PHP 从一个"个人主页工具"的业余语言变成了"可以运行大型网站"的专业语言。

## HTML 中的那扇窗

PHP 的核心设计决策——"在 HTML 中开窗户"——值得多说几句，因为它解释了为什么 PHP 赢了。

对比一下：1995 年如果你用 Perl 写动态网站，你写的是一个独立的 Perl 脚本，然后这个脚本用 `print` 语句输出整个 HTML 页面。你的代码大概长这样：

```perl
print "Content-type: text/html\n\n";
print "<html>\n<body>\n";
print "<h1>Welcome</h1>\n";
print "<p>Hello, $name</p>\n";
print "</body>\n</html>";
```

你的代码在"输出 HTML"。HTML 是你在 Perl 字符串里引号包裹的"数据"。

PHP 把这个关系完全颠倒过来：

```php
<html>
<body>
<h1>Welcome</h1>
<p>Hello, <?php echo $name; ?></p>
</body>
</html>
```

你的页面就是一个 HTML 文件——只是在需要"动态"的地方，你用 `<?php ?>` 开了一扇窗户，往里看一眼数据库，然后把结果放在这个位置。你的代码在"嵌入 HTML"。HTML 是主体，代码是插入的附件。

这个差异对"普通人"有巨大的意义。1995 年到 2000 年间，网页设计师——一个正在成型的职业——大部分使用 Dreamweaver 或 FrontPage 来制作网页。这些可视化编辑器能处理 HTML，但不能处理 Perl 的 `print` 语句。设计师可以在 Dreamweaver 中编辑一个 PHP 文件中的 HTML 部分——只要不碰 `<?php ?>` 块里的东西，页面就能正常工作。他们不需要理解变量作用域、函数调用、甚至是"程序"的概念——他们只需要知道：在某个位置插一段代码，就能从数据库里读数据。

这是 PHP 与其他所有服务器端语言的根本区别。Java 的 Servlet 要你写一个完整的 Java 类然后编译部署。ASP 虽然也允许 HTML 中嵌入 VBScript，但它和 Windows/IIS 绑定。ColdFusion 是商业软件，需要购买许可证。只有 PHP 是免费的、开源的、在任何共享主机上都能跑的——而且它的"嵌入"模式比所有竞争方案都更自然。

## LAMP 栈——免费的午餐

1998 年，德国《c't》杂志的记者 Michael Kunze 写了一篇文章。他在文章里提出了一个缩写：LAMP——Linux, Apache, MySQL, PHP（或 Perl 或 Python）。他的核心论点是：这四个开源软件加在一起，构成了一套足以匹敌商业 Web 开发平台的免费方案。

对比当时的企业级方案：微软的解决方案是 ASP + IIS + SQL Server，许可证费用是每台服务器几千美元，而且你被锁定在 Windows 上。IBM 的方案是 WebSphere + DB2，价格可以到六位数。Oracle 的方案是 Oracle Application Server + Oracle Database，同样昂贵。而 LAMP 的全部组件都是免费的——你不需要为任何软件支付许可证费用。你只需要一台服务器（或者一个共享主机的账号，月费 10 美元），装一个 Linux 发行版，apt-get install 或者 yum install 四个组件，就拥有了一个完整的企业级 Web 平台。

但这不只是"免费"的问题。LAMP 的另一个关键特性是"开箱即用"的组合性。Apache 通过 mod_php 模块把 PHP 解释器嵌入到了自己的进程里——不再需要为每个请求 fork 一个 CGI 进程。MySQL 提供了一个免费的、可用的、性能足够好的关系数据库。Linux 提供了一个稳定的、类 Unix 的操作系统环境。它们的组合——mod_php 的连接让 PHP 能直接在 Apache 进程内运行，PHP 的 `mysql_connect()` 让连接数据库只需要一行代码，Linux 的文件权限和进程模型让安全性可控——形成了一个流畅到几乎无缝的开发体验。

2000 年代初，无数小型网站公司、个人站长、博客作者、论坛管理员是靠着 LAMP 栈起步的。你花 10 美元一个月买一个共享主机，主机商已经给你装好了 Apache、MySQL、PHP 和 phpMyAdmin（一个用 PHP 写的数据库管理工具）。你登录 cPanel（也是用 PHP 写的），上传一个 phpBB 论坛程序（PHP 写的），解压，填写数据库名和密码——论坛就跑起来了。整个过程不需要理解 Linux 也不是什么"高手"——你只是上传压缩包然后点了几下鼠标。

在 LAMP 之前，一个"中学生做论坛"的故事几乎不可能发生。在 LAMP 之后，这类故事太常见了——无数人在 2000 年代初学会了"在网上搭点东西"，不是因为他们读了计算机系，而是因为他们发现上传一个 PHP 文件就能让网站变活。

## WordPress——杀手应用

PHP 的低门槛让一个生态长了出来。2003 年，一个 19 岁的美国青年 Matt Mullenweg 遇到了一个问题。

他是休斯顿大学的学生，Linux 用户和开源的爱好者。他写博客——当时的平台是 b2/cafelog，一个由 Michel Valdrighi 用 PHP 写的博客系统。b2 很好用——轻量、简单、让写博客这件事回归到"写作"本身而不是"技术支持"。但 2003 年初，Valdrighi 停止了 b2 的开发。用户社区里弥漫着焦虑——这个大家依赖的平台死了。

Mullenweg 在博客上写了一篇文章，标题叫《The Blogging Software Dilemma》。他说：b2 的开发停止了，现有的 fork 各立山头，没有一个统一的社区方向。他认为最好的出路是 fork b2，在它的基础上做一个新的、更现代的平台。他在帖子中问：有谁愿意一起做？

第一个回复他的人是 Mike Little——一个开发者的回帖成为了 WordPress 的起点。

2003 年 5 月 27 日，WordPress 0.70 发布了。它的名字是 Mullenweg 的朋友 Christine Selleck Tremoulet 建议的。"WordPress"——Word 和 Press 的组合，像是"词"和"印"的意象。Mullenweg 后来在一次演讲中说："Christine 说，为什么不起一个简单的、不让人害怕的名字？"

然后 2004 年，一个意外的"市场冲击"彻底改变了 WordPress（以及 PHP）的轨迹。

Movable Type——当时最流行的博客平台之一，使用 Perl 而非 PHP——于 2004 年更改了它的许可条款。Six Apart，Movable Type 的所有者，将它的免费版从"无限博客"限制到"三个作者和三个博客"。对已经用 Movable Type 搭建了多人博客的网站来说，这相当于一夜之间从免费变成每年数百美元的订阅费。

社区炸了。无数 Movable Type 的用户开始寻找替代品。WordPress 当时还很年轻——版本号只有 1.2——但它是免费的、自托管的、PHP/MySQL 的、运行在任何 LAMP 环境上的。它不像 Movable Type 那样需要 Perl 的复杂配置。它的安装过程简单到令人发指：下载压缩包、解压到服务器、创建一个数据库、运行 `wp-admin/install.php`——五分钟，一个新博客。

从 2004 年底到 2005 年，一波巨大的迁移潮从 Movable Type 涌向 WordPress。这个迁移对 PHP 生态的影响是全方位的：WordPress 的爆红意味着 PHP 被推上了"CMS 语言"的宝座。以前你说"我要做个博客"，别人会问"你用什么语言"；现在别人问"你用 WordPress 吗"——语言本身消失了，变成了基础设施。PHP 不再是你在评估的技术选择——它像你呼吸的空气一样默认存在。

2005 年后，WordPress 的生态开始自我加速。开发者写插件（评论管理、SEO、缓存、社交分享——你想到的功能，大概率有一个 WordPress 插件），设计师做主题（从免费到商业，从简到复杂），主机商优化服务器（"WordPress 优化主机"成为一个独立的品类），用户写内容。这个飞轮一旦开始转动，几乎不可逆转。

到 2024 年，W3Techs 的数据显示，43% 的网站使用 WordPress。这不是"43% 的网站使用某个内容管理系统"——这是 43% 的网站使用同一个系统。这中间包括了《纽约时报》、白宫官网、索尼、迪士尼、微软、Facebook 新闻室——以及大量的个人博客、小型企业网站、在线商店、论坛、课程平台。

WordPress 的成功直接起源于 PHP 的两个特性：简单到任何人都能部署，灵活到可以装插件变成任何东西。而 PHP 的一切——它的嵌入模式、它的宽松语法、它对"草台班子"的容忍——都是实现这两点的前提条件。

## 负面遗产

PHP 付出了代价。

低门槛意味着大量写得糟糕的代码在互联网上运行。这不是一个假设——它是 PHP 生态持续至今的现实。2000 年代中后期的 PHP 代码质量广受诟病，其核心原因是一个叫 `register_globals` 的特性。

`register_globals` 是 PHP 早期的一个默认设置：当用户在表单里提交一个参数 `username`，PHP 自动把它变成了 `$username` 全局变量。听起来很方便——你不写 `$_GET['username']` 或者 `$_POST['username']`，直接用一个全局变量。但这意味着任何用户都可以通过 URL 参数任意设置变量值。如果你写了一段代码像 `if ($admin) { delete_all_users(); }`，一个用户在 URL 里加一个 `?admin=1`，你的管理后门就敞开了。

这个特性在 PHP 4.2.0（2002 年）中被默认关闭，但它造成的伤害已经无法挽回——无数用旧版本 PHP 开发的网站直接暴露在 SQL 注入和远程代码执行的威胁下。

函数命名的不一致成为程序员茶余饭后的笑谈。

```php
// 标准库里的参数顺序完全不一致
strpos($haystack, $needle);      // 第一个参数是"干草堆"
array_search($needle, $haystack); // 第一个参数是"针"
// 为什么？没有人知道。
```

有些函数名来自它们底层调用的 C 库——`htmlspecialchars` 是一个"准确定义功能但令人难以记住"的名字。有的函数名甚至在同一个功能域里使用了不同的命名风格——`strpos`、`str_replace`、`strstr`（小写下划线风格），和 `MySQLi`、`DateTime`（驼峰风格）并存于同一个标准库里。PHP 没有在早期定义一套统一的命名规范——因为早期没有"规范"这个概念，Lerdorf 只是把 C 库的名字直接搬过来用。到了后来社区成熟了，规范产生了，但已有的函数名不能改了——改了会破坏几百万行现有代码。

更严重的问题是安全意识的缺失。PHP 在很长一段时间里缺乏对 SQL 注入、XSS、CSRF 等 Web 安全威胁的语言级防御。如果一个程序员在 2003 年写了一个 PHP 留言板，他很可能这么写：

```php
$query = "SELECT * FROM users WHERE id = " . $_GET['id'];
```

如果攻击者在 URL 里传入 `id=1; DROP TABLE users`——这就是历史上无数被删除的数据库的由来。PHP 没有提供类似参数化查询的语言级工具——这些责任完全落在了开发者身上。

但硬币的另一面是：正是 PHP 的普及让 Web 安全从"极客话题"变成了"基础常识"。2000 年代，OWASP Top 10 的榜单上 SQL 注入常年占据榜首——这不是偶然。大量的 PHP 网站被攻破、被挂马、被拖库——这些惨痛教训倒逼了整个行业的认知升级。今天，即使是一个刚学 PHP 三个月的初学者，也可能在教程里看到"使用 prepared statements"的警告。这个认知积累的过程是痛苦的——但它最终让 Web 开发的安全门槛提高了。你不会在其他语言生态中看到如此广泛的安全教育——因为其他语言的"安全训练"发生在程序员正式进入这个领域之前，而 PHP 的安全教育发生在"你已经写了几千行代码并且删了一次生产数据库之后"。

## 今天的 PHP

你可能会听到人说 PHP 死了。这个说法和 PHP 本身一样老了——2005 年就有人说 PHP 要死，2010 年又说，2015 年再说，2020 年了还在说。而 PHP 的 W3Techs 数据是：76% 的已知网站使用它——"已知网站"指的是那些能被 W3Techs 识别的网站后台语言的站点。这个数字在过去十年里只非常缓慢地下降着——不是因为 PHP 在变好，而是因为它在 2000 年代占据的位置实在太大。

PHP 7 是一场重大的翻身仗。2015 年发布的 PHP 7 引入了 phpng 项目——由 Dmitry Stogov、Xinchen Hui 和 Nikita Popov 领导的 Zend Engine 重写。phpng 把 PHP 内部的数据结构变得更紧凑，内存占用减少了，CPU 缓存命中率提高了。WordPress 的基准测试显示，PHP 7 比 PHP 5.6 快了几乎一倍——对很多网站管理员来说，升级到 PHP 7 就像免费换了台服务器。

PHP 8 在 2020 年发布了 JIT 编译器——Just-In-Time Compilation。这意味着 PHP 在某些计算密集型的场景下可以把代码编译成机器码直接执行，性能可以再翻一倍。虽然 Web 开发场景中 JIT 的收益并不如在数值计算中那样显著——因为 Web 请求通常被 I/O（数据库查询、文件读取、网络请求）限制，而非 CPU——但它仍然是一个重要的信号：PHP 的开发团队没有停下脚步。

Laravel——2011 年由 Taylor Otwell 创建的 PHP 框架——完全重塑了 PHP 在程序员心中的形象。它引入了优雅的语法、现代化的 ORM（Eloquent）、干净的模板引擎（Blade）、依赖注入容器、队列系统、任务调度、内置的认证系统。Laravel 证明了 PHP 可以写出优雅、架构清晰、让人愉悦的代码——它不是"最好的语言"，但它不再是一个被嘲笑的对象。

但不可否认的事实是：PHP 不再是年轻人的首选语言。2000 年代，一个高中生在共享主机上解压一个 phpBB 论坛就能开启编程之旅。今天，那个高中生的"第一次编程体验"更可能发生在 Replit 上的 Python、Vercel 上的 Next.js、或者 Arduino 上的 C++。PHP 的低门槛生态优势——曾经是它的核心竞争力的部分——已经被现代化的云平台和工具链稀释了。

但这不意味着 PHP 消失了。它仍然在运行着互联网上接近一半的网站。它运行着 WordPress，而 WordPress 运行着互联网上 43% 的站点。它运行着 Wikipedia（MediaWiki 是用 PHP 写的）、Facebook（虽然 Facebook 后来创建了 HHVM 和 Hack，但本质上是一个 PHP 生态的演化）、以及无数的电子商务网站（Magento、WooCommerce）。当你浏览一个网站时，在"不知道它是用什么做的"的情况下，它大概率的答案是 PHP。

## 建站权的下放

让我们回到最初的问题：普通人能做动态网站吗？

PHP 的回答是"能"。它的方式是：把代码嵌进 HTML，消除一切不必要的学习步骤，容忍混乱、不一致、非专业的设计——只要你还"能把东西做出来"。这种哲学不是写进 PHP 的设计文档里的，而是在 Lerdorf 一个一个回答用户邮件的过程中长出来的。从"你不需要 root 权限"到"你不需要 Perl"到"你不需要访问日志文件"——每一行每一个功能，都是在回答同一个问题：还能再降低一点门槛吗？

PHP 把这个门槛降到了人类历史上从未有过的低。1994 年，一个 14 岁的孩子能靠 FTP 上传一个 PHP 文件，然后搭出一个带数据库的留言板。这件事本身就是一个小的社会变革。在 PHP 之前，"我有东西想说"和"我能把它放到网上让别人回应我"之间隔着一道高墙——你要么学 Perl/CGI，要么花钱雇人做。PHP 和 LAMP 拆掉了那道墙。一个没有"正统计算机教育"的人也可以在网上建一个属于自己的发言空间。

这道墙的拆除催生了后来的很多东西：博客浪潮（WordPress）、论坛社区（phpBB、vBulletin）、草根电商（osCommerce、Magento）、维基百科（MediaWiki）、以及无数个人站长发布天文、音乐、小说、收藏品等各类兴趣网站的"黄金时代"。每一个搭了一个 phpBB 论坛就开始谈论"虚拟社区"的站长——他们都是 PHP 的暗线。PHP 没有发明 UGC（用户生成内容）的概念，但它提供了 UGC 的技术前提：一个没有技术背景的人可以建一个让其他人也能贡献内容的网站。

Rasmus Lerdorf 在 1993 年只是想知道谁看了他的个人主页。35 年后，他的"小工具"开启了一个什么样的连锁反应？

43% 的网站跑着 WordPress。WordPress 是 PHP 写的。PHP 跑在 Zend Engine 上。Zend Engine 是 Andi Gutmans 和 Zeev Suraski 重写的。而 Zend（Zeev + Andi）是他们在以色列理工做电子商务时发现自己需要更好的解析器而开始的。这一切的起点，是一个来自格陵兰的、穿着 T 恤的工程师在 Usenet 上发的一封邮件。

"I don't know how to stop it。" 这是 Lerdorf 的原话。

他确实没有让它停下来。它也不需要停下来。它只是在继续运转着，为互联网上那些不显眼的、却至关重要的东西——评论、博客、表单、购物车、会员系统——提供着底座。

## 人物

![](/images/rasmus-lerdorf-young.jpg)

*Rasmus Lerdorf（1968–），PHP 的创造者。出生于格陵兰迪斯科岛，滑铁卢大学系统工程系毕业。他不是计算机科学家，是一个"遇到问题就写工具"的工程师。PHP 最初只是他用来跟踪访客的工具——"我完全不知道怎么写一门编程语言，"他说，"我只是加下一个合理的功能。"*

![](/images/andi-gutmans-young.jpg)

*Andi Gutmans（1972–），Zend Engine 的共同创造者。以色列理工的学生，1997 年和 Zeev Suraski 一起重写了 PHP 的解析器——因为他们做电子商务项目时觉得 PHP/FI 的解析器不够用。后来联合创立 Zend Technologies。"Zend" 是 Zeev + Andi 的名字组合。*

![](/images/zeev-suraski-young.jpg)

*Zeev Suraski（1970–），Zend Engine 的共同创造者。Andi 在以色列理工的同学。他们俩的引擎被 Lerdorf 评价为"比我做的好得多"——没有 ego 的创始人加上两个才华横溢的学生，这个组合奠定了 PHP 的专业化基础。*

![](/images/matt-mullenweg-young.jpg)

*Matt Mullenweg（1984–），WordPress 的联合创始人。19 岁时因为 b2/cafelog 停止开发而 fork 了它的代码，创建了 WordPress。2004 年 Movable Type 变更许可条款引爆迁移潮，WordPress 成为全球最流行的 CMS。到 2024 年，43% 的网站使用 WordPress。*

![](/images/lamp-stack-architecture.svg)

*LAMP 栈架构——Linux、Apache、MySQL、PHP。四个开源软件的组合创造了一个完全免费、完全开放的 Web 开发平台。这个缩写由德国记者 Michael Kunze 在 1998 年提出，它让中学生用零成本就能上线一个动态网站。*

---

PHP 的故事是一个关于"够了就是够了"的故事。它不是一个完美的语言，不是设计者的杰作，不是计算机科学的光辉范例。它是一个实用主义者——Rasmus Lerdorf——在面对"做一个网站太麻烦了"这个现实问题时，给出的一个足够好的回答。

在技术演进的河流中，PHP 曾经是那条足够宽的船。它不漂亮，不优雅，甚至有点笨拙——但它载着数以百万计的普通人驶向了互联网的彼岸。那些人在船上建了博客、论坛、商店、社区——然后互联网成了今天的样子。

Fortran 说科学家可以不靠程序员自己编程。Lisp 说计算机可以做符号处理。C 说操作系统可以用高级语言写。SQL 说数据可以问。JavaScript 说浏览器可以运行应用。而 PHP 说了一句话，听起来最简单，但可能最有力量——"你也能建一个网站。"
