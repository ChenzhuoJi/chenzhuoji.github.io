这个栏目的十七篇文章，讲了十七个东西：十四种语言，一个平台，一篇前言，一篇结语。

但说实话，我应该先坦白一件事——这些选择是我拍脑袋定的。

不是说我没有理由。每种被选进来的语言都对应着一个不可替代的历史节点——Fortran 是编译器本身、C 是操作系统、SQL 是数据查询、JavaScript 是浏览器、Python 是 AI——你可以看到一条清晰的脉络在串联它们。但几千种编程语言里只选十四种，漏掉的一定比放进来的多。

COBOL 是第一个让我纠结的名字。1959 年，美国国防部说"我们需要一门商用语言"，于是 Grace Hopper 和她的团队做出了 COBOL。它的语法像英语一样啰嗦——`ADD YEAR TO AGE GIVING AGE`——但在 1960 年代，它定义了什么叫"企业软件"。直到今天，全世界的银行和保险公司还在跑着几十亿行 COBOL 代码。那些系统不换，不是不想换，是不敢换——替换一个运行了五十年的核心交易系统的风险比留着它大得多。COBOL 没有放进来的原因很简单：它的故事是委员会驱动的，没有一个"一个人在房间里写出第一行代码"的时刻。它的精神是集体的，这个栏目的叙事是个人英雄主义的——两者不匹配。

Smalltalk 是另一个。1972 年，Alan Kay 在 Xerox PARC 设计了一门"纯面向对象"的语言——它的哲学是"一切都是对象，包括整数"。你发消息给一个对象，它给你回复。Smalltalk 太超前了，图形界面、鼠标、窗口——它在 1972 年的实验室里就把这些东西都做了出来。但它死在 Xerox 的商业无能手里——PARC 发明了这一切，却没让任何一样东西走出实验室。C++ 和 Java 后来接过了"面向对象"的火炬，但没有人像用 Smalltalk 那样用过它们——它们把面向对象做成了"一种工具"，而不是"一个世界"。

Perl 呢？Larry Wall 是一个语言学家出身的程序员，他在 1987 年做了一门"文本处理的瑞士军刀"。Perl 的口号是 TMTOWTDI（There's More Than One Way To Do It）——一件事情的写法不止一种。这在当时是解放，在今天看是一种诅咒。Perl 的正则表达式语法至今无人超越，但它可读性的灾难让它永远成不了主流——你三个月前写的 Perl 代码，你自己都看不懂。它曾经是 CGI 编程的王者——1990 年代每一个动态网站后面都是 Perl——但 PHP 抢走了它的王座，Python 抢走了它的未来。

Ada 是五角大楼的产品。Pascal 是教学语言。Erlang 是爱立信的电话交换机语言。Lua 是巴西人做的嵌入式脚本语言。Dart 是 Google 推的 JavaScript 替代品。Kotlin 是 JetBrains 为 Android 做的更好的 Java。TypeScript 是 JavaScript 的"带类型版本"——按照使用人数来说，它应该被放进来的。但我选了 JavaScript 作为那个时代的代表——因为 TypeScript 没有改变"JavaScript 可以干什么"，它改变了"JavaScript 可以怎么组织"。

每一门语言的故事都很精彩。每一门语言都代表着一群人的世界观。但一个专栏只能有这么多篇文章，所以剩下的——就让它们在这次对话中被提到一次吧。它们值得。

---

我真正想说的其实是另一件事。

你回头看这个栏目里的那些人——John Backus、John McCarthy、Ken Thompson、Dennis Ritchie、Edgar Codd、Bjarne Stroustrup、James Gosling、Brendan Eich、Rasmus Lerdorf、Ross Ihaka、Robert Gentleman、Guido van Rossum、Yukihiro Matsumoto、Rob Pike、Ken Thompson（又一次）、Graydon Hoare、Linus Torvalds、Tom Preston-Werner。

他们改变了世界。这是一个已经被用滥了的句子，但放在他们身上是字面意义上的——你今天写每一行代码、打开每一个网页、用每一个 App，都在用他们七十年间设计出来的工具。你的代码在 C 语言的操作系统上跑，在 JavaScript 的浏览器里渲染，通过 SQL 数据库存取，被 Python 和 Go 的后端服务连接在一起。你们素未谋面，但你在依赖他们每一个人的智慧。

但你听说过几个名字？

John Backus 发明了编译器——这门学科后来养活了几百万工程师。但你在街上随便问一个人"John Backus 是谁"，他会以为是 Backstreet Boys 的成员。Bjarne Stroustrup 让面向对象成为了工程标准，维基百科上他的词条浏览量还不如一个二线 YouTuber 的一天的视频播放量。Rasmus Lerdorf 让每个普通人都能搭一个动态网站——PHP 至今运行在超过 70% 的网站上——但你几乎在任何场合听到他的名字。

这不是他们的失败，这是一种奇怪的规律。

科技行业的聚光灯永远打在几个人的身上——Jobs、Gates、Zuckerberg、Musk——他们在商业的舞台上，在发布会的大屏幕上。媒体的摄像机对着他们。他们的名字是家喻户晓的。而设计了这个行业底层工具的这些人——那些让操作系统能跑、让数据库能查、让浏览器能渲染、让网页能动态生成的人——他们在媒体的视野之外，在维基百科的词条里，在一些被遗忘的技术会议记录里。

而且——他们大多数人是程序员。不是"技术出身的企业家"，是程序员。我们在文章里读到了他们的天才时刻——Backus 在 4K 内存里做蒙特卡洛优化、Thompson 两周写出 Git、Brendan Eich 十天做出 JavaScript——但读完整篇文章你会发现另一件事：他们也做着程序员都会做的事。改 bug、看文档、写注释、和同事争吵接口设计、在深夜盯着屏幕怀疑人生。Linus Torvalds 在写出 Git 之前也摔过键盘，Bjarne Stroustrup 在让 C++ 兼容 C 的决策上也纠结过好几年，Guido van Rossum 在 Python 2 到 3 的迁移上犯了可能是开源世界最大的错误，James Gosling 的 Java 第一次被 Sun 内部的人——Sun 内部的人——嘲笑过。

他们是天才，但他们也是打工人。

这可能是这个栏目在暗地里想说的东西——技术的进步不是靠几个站在山顶的人挥手一指，是靠几万个坐在屏幕前的人一行一行敲出来的。被我们记住名字的人只是那几万人里的冰山一角——他们幸运地出现在了正确的时机，解决了正确的问题，然后被历史记住了一部分。剩下的人——那些写了操作系统的大半代码、写了编译器里最枯燥的部分、写了文档、修了最不显眼的 bug 的人——他们连冰山一角都不算。

但这个栏目只能做到这里。十七篇文章，十四种语言，十四个名字。我没办法把每一个贡献过代码的人写进来——那样的话十七万字都不够。但至少，我可以让这些被选中的名字被更多人读到。

写这个栏目的时候，我一直在想一个画面：2026 年的某一天，一个程序员坐在屏幕前，打开编辑器，敲下了第一行代码。他不是 Backus，不是 Ritchie，不是 Torvalds——他是一个普通公司的普通工程师。但他在用 C 语言写的操作系统上、在一个 JavaScript 的编辑器里、用 Python 写一个后天要上线的功能。他正在穿越七十年的历史——每一个字符都踩在前人的肩膀上。

他没有意识到这件事。

但这就是"时代群像"的意思——不是站在领奖台上的那几个人，是每一个在深夜改着 bug、在日志里翻滚、在 Stack Overflow 和官方文档之间来回切换的人。创造这个数字世界的人，和你我一样。

他们的故事，就是这个栏目想要讲的东西。

现在，说完了。
