写完了。

去年冬天决定做这个栏目的时候，我没想到会写这么多。从 Fortran 到 GitHub 特别篇，加上前言和结语，拢共十七篇，十多万字。回头看的时候，我自己都有点恍惚——这些故事居然都是真的。

不是"根据真实事件改编"的那种真。是字面意义上的：有人在 1957 年用一行数学公式让真空管计算机算出了导弹弹道；有人在 1960 年发明了一种语言，让计算机可以处理"代码"这个词本身；有人在 2005 年因为生气，两个星期写出了一个版本控制系统，二十一的后全世界还在用。

但你知道吗？写这个栏目最难的部分，不是查资料，不是组织叙事——而是选。

选哪些语言放进来。

人类从 1940 年代到现在，创造了几千种编程语言。我选了十四种（加上一个平台）。每一个选择背后都是一次纠结。

COBOL 为什么没放？这个决定让我犹豫了很久。没有 COBOL，就没有后来的商用计算——它定义了"数据记录"、定义了"报表生成"、定义了"企业软件的开发流程"。但 COBOL 的故事是反叙事的——它没有"一个扎克伯格在宿舍里写了 Facebook"那种瞬间。它是一个委员会的标准，是五角大楼的要求，是商用计算机买家集体投票的结果。它很重要，但它的故事不适合这个栏目的讲述方式。

Ada 呢？Perl 呢？Smalltalk 呢？Pascal 呢？Erlang 呢？Scala 呢？Kotlin 呢？TypeScript 呢？

每一个都是"曾经想过要写，最终没有写"的名字。不是它们不重要——是篇幅有限，而我想讲的不是一个完整的编程语言编年史。我想讲的是**人和机器之间，每一次降低对话门槛的瞬间**。

按照这个标准，COBOL 和 Ada 没有提供新的"降低门槛"的方式。Smalltalk 提供了（面向对象），但它的故事被 C++ 和 Java 接力了。Perl 提供了（文本处理的 DSL），但它的生态位被 Python 接管了——Unix 管理员现在会用 Python 写脚本。Erlang 提供了（Actor 模型），但 Go 和 Rust 后来用更流行的方式解决了并发问题。

每一个被放进去的语言，都对应着一个不可替代的"门槛降低"的时刻。

Fortran —— 让科学家不用学汇编。
Lisp —— 让程序可以处理程序本身。
C —— 让操作系统可以用高级语言写。
SQL —— 让非程序员也可以问数据库问题。
C++ —— 让面向对象成为工程实践。
Java —— 让跨平台不再是梦话。
JavaScript —— 让浏览器从页面变成了应用平台。
PHP —— 让每个人都能搭一个动态网站。
R —— 让统计学家有了自己的方言。
Python —— 让胶水变成了通用语言，最终成了 AI 时代的普通话。
Ruby —— 让程序员相信编程可以是快乐的。
Go —— 让云计算时代的工程师不再被 C++ 折磨。
Rust —— 让内存安全不需要垃圾回收。
GitHub —— 让所有语言的代码有了一个共同的社交网络。

每一篇都在讲同一个主题：**门槛降低了，更多人进来了，世界变了。**

---

写这个栏目的过程中，有几个瞬间让我印象特别深。

第一个是 Fortran 的蒙特卡洛优化。1957 年，在一个只有 4K 内存、随时可能真空管烧毁的机器上，Backus 的编译器居然在做蒙特卡洛模拟来优化代码布局。你不知道这回事的时候，Fortran 就是一个"古老的语言"。你知道以后——你对整个软件工程的想象力都会被刷新。那个时代的人在 4K 内存里做出的事情，今天的人用 16GB 内存都做不出来——不是技术问题，是想都想不到可以那么做。

第二个是 Rust 的所有权系统。Graydon Hoare 在 Mozilla 的办公桌上想出的那个"谁借了谁"的检查机制，本质上是一个编译期的数学证明——它证明你的程序没有内存错误。你不需要垃圾回收，不需要手动释放内存，编译器替你把所有的可能性都检查了一遍。这是一个五十年都没人解决的问题——从 C 语言诞生那天起，内存安全就是系统编程的噩梦。2015 年，Rust 给出了一个优雅到让人想哭的答案。

第三个是结语里那句 "Hello, World." 没有代码框，没有语法高亮，没有语言的 logo——只有一行自然语言。写那一段的时候，我忽然觉得，整个栏目其实是一个巨大的铺垫——十七篇文章的存在价值，就是为了最后那篇结语。

从让机器理解 `y = x + 1`，到让机器理解"帮我写一个从 PDF 里提取表格的 Python 脚本"——这中间隔了七十年。而我是说，作为写代码写了十几年的人，我不知道该为此感到兴奋还是伤感。

兴奋的地方显而易见：AI 写代码了。下一个十年，会有更多的人参与软件开发——不是因为他们学会了编程语言，而是因为编程语言学会了自然语言。

伤感的地方也显而易见：程序员引以为傲的"手艺"——那种把复杂逻辑拆解成精确代码的能力——正在变得不那么稀缺。当你的需求可以用自然语言说出来然后自动变成代码的时候，"写代码"这件事本身的稀缺性在下降。

但我想说的是：这不等于"编程不再重要"。

你想想，Fortran 出现的时候，汇编程序员也觉得"写代码的门槛在下降"。他们是对的。但门下降之后发生了什么？不是程序员失业了——是程序员变多了，做的事情变大了。Fortran 让物理学家可以自己写程序；C 让操作系统工程师可以写出更复杂的系统；JavaScript 让网页设计师可以做交互。每一扇门打开之后，进来的是一群新人，他们在新世界里做出了原来的程序员做梦都想不到的东西。

自然语言也是一样。当你说"帮我写一个分析销售数据的工具"的时候，你并不是在"驯化"AI——你是在**沟通**。你在告诉它你的意图、你的行业、你的数据特征。而这些——沟通、判断、负责任——是真正的"编程"永远不会贬值的那一部分。

所以这十七篇文章，表面上是在写编程语言的历史，其实是在写一件事：**人类一直在降低"和机器对话"的门槛，而每一次降低，都让世界变得更大一点。**

---

有几件事我想坦白。

第一，这个栏目的阅读顺序不是固定的。你可以从头看到尾，感受时间的纵深感；也可以挑你感兴趣的语言跳着读——每篇文章都是独立的故事。但如果你问我的建议，我推荐你看完前言后跳去特别篇，再跳去结语。这三篇构成了一个完整的弧线：开始之前 → 平台的力量 → 结束之后。

第二，我写这个栏目的时候尽量做了事实核查，但七十年间发生的事，有些细节在不同来源里有不同说法。如果你发现某个地方有出入——欢迎你告诉我。这个栏目不是历史教科书，它是**讲故事的人对历史的一次致敬**。致敬不应该出错，但如果出错了，至少出发点是好的。

第三，也是最重要的——谢谢你的阅读。

一个栏目写了十七篇，没有读者就是自言自语。你看到了这里，说明你对"代码"这件事多少有些在意。不管你是程序员、设计师、学生、还是单纯对技术史好奇的人——你的注意力是这个栏目存在的原因。

写这个栏目的时候，我重新意识到了一件事：**编程语言不是技术，它们是文化。** Fortran 是 1950 年代大型机文化的产物；Lisp 是 MIT AI 实验室学术文化的产物；PHP 是个人站长文化的产物；R 是统计学家反叛商业软件文化的产物。每一种语言都带着创造者所在的那个世界的烙印。

而自然语言作为"最后一门编程语言"——它带着整个人类文化的烙印。因为自然语言是所有人共享的。

这或许就是这条暗线的终点：从一开始，我们就在试图让机器理解人类。七十年后，机器终于开始懂了。而它懂的方式，和我们彼此理解的方式一样——靠说，靠写，靠问。

---

列位，咱们这场书说到这儿，就到一段落了。

从插线板到自然语言，从真空管到神经网络，从一行数学公式到一段对话——七十年的路，走了十七篇文章。

我没有什么大道理要总结。我只是觉得，活在这个时代是一件很幸运的事——我们亲眼看到了计算机从房间那么大变成口袋那么小，从只懂 0 和 1 到能听懂"帮我把那个 PDF 里的表抽出来"。

这个变化不是天上掉下来的。是 John Backus 躺在医院里想着怎么偷懒想出来的。是 Dennis Ritchie 在贝尔实验室的地下室里一行一行敲出来的。是 Linus Torvalds 在波特兰的书房里因为生气写出来的。是三个年轻人在旧金山的酒吧里聊着 Ruby 和 Git 聊出来的。

每一行代码背后都有一个人。

每一门语言背后都有一个故事。

这十七篇，就是那些人的故事。

感谢你，听我说完。

咱们下个栏目见。
