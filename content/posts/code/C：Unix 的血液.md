## Hello World

```c
main() { printf("hello, world\n"); }
```

*这是 1978 年 K&R《The C Programming Language》第一章第一个例子的完整代码。11 个单词——在一个几百页的编程书里，它比任何一段文字都更清楚地说出了 C 的性格：极简、直接、不加修饰。它假设你知道 `main` 是什么，假设你知道 `printf` 从哪来，假设你不需要被解释什么叫"程序"。它信任你。*

![](/images/c-logo.svg)

*C 语言的经典 logo——图标中的六边形象征着它在系统底层、硬件交互中的核心地位，而中心的 “C” 则直接点明了它的身份，与 Dennis Ritchie 和 Ken Thompson 在贝尔实验室创造的这门语言的气质完全一致：极简、直接、不加修饰。C 自 1972 年诞生以来一直是系统编程的绝对主宰——操作系统、编译器、嵌入式设备的核心几乎全是用 C 写的。这个 logo 没有多余的装饰，就像 C 本身：它信任你，但不会替你做事。*

2011 年 10 月 12 日，Dennis Ritchie 在新泽西州 Berkeley Heights 的家中去世，享年 70 岁。他独自生活，被发现时已经走了几天。同一周，全世界的新闻头条都在报道 Steve Jobs——苹果创始人五天前去世，人们排着队在 Apple Store 门口放鲜花、贴便签、哽咽着回忆这位改变了消费电子行业的天才。几乎没有一家主流媒体为 Ritchie 停下一分钟。那些同时报道了两件事的媒体，大多数也只是在文章末尾加了一句"顺便一提，Unix 操作系统和 C 语言的设计者也去世了"。

但你的手机在跑他的代码。你写这篇文章的电脑在跑他的代码。你用来阅读这篇文章的路由器、服务器、基站——每一层都在跑他的代码。你打开任何一个 App，它的底层大概率是用 C 写的。你访问任何一个网站，背后从操作系统到 Web 服务器到数据库——每一个关键组件要么本身就是 C 写的，要么是用 C 写的解释器去跑的。你是一个生活在 2026 年的人，你每分每秒都在使用 Dennis Ritchie 四十年前创造的成果，而你可能从来没有听说过他的名字。

《经济学人》在他去世后写了一篇讣告，里面有一句话说得精准："Dennis Ritchie 是 IT 行业里几乎从未被提起但影响最大的那个人。"

这篇讣告没有解释的问题更值得追问：为什么一个人创造了如此根本的东西，却如此不为人知？为什么 C 语言——这个在诞生五十多年后仍然是系统编程的绝对主宰——它的创造者不是像 Steve Jobs 那样的明星？

答案藏在 C 和 Unix 的起源里。那是一个关于"想玩游戏"和"顺手做个操作系统"的故事。

## 一个游戏和一个操作系统

1969 年的秋天，贝尔实验室的 Multics 项目正式宣告失败。

Multics 是一个野心勃勃的尝试：MIT、通用电气和贝尔实验室联手，要做一个"计算公用事业"——像电力和电话一样，计算应该是随时可用、分时共享的。想法很美，但执行遇到了所有大型联合项目的典型困境：进度拖延、预算超支、各方目标不一致。贝尔实验室的管理层决定退出。GE-645 大型机被搬走了，留下一群研究员突然没了机器用。

其中一个研究员是 Ken Thompson。他 26 岁，从加州大学伯克利分校拿到硕士学位刚三年，写代码的天赋已经在贝尔实验室小有名气。Thompson 有一件特别想做的事：他写了一个叫 Space Travel 的游戏——模拟太阳系飞行，玩家要驾驶一艘飞船在二维的太阳系模型里穿行，在各种行星和卫星的引力场中完成着陆。但他找不到一台能跑它的机器。当时可用的那台 PDP-7 小型机——DEC 公司的上一代产品——只有 8K 个 18 位字的内存，没有操作系统，没有软件，几乎是块废铁。Thompson 不愿意放弃。他做了一件任何一个正常工程师都不会做的事：既然没有操作系统，那我就写一个。

于是他开始在 PDP-7 上写一个操作系统的原型。他甚至不能在 PDP-7 上直接写——因为那台机器上连个像样的编程工具都没有。他用的是贝尔实验室的 GE-635 机器，在上面写 PDP-7 的汇编代码，然后生成纸带，把纸带拿到 PDP-7 上去跑。每次修改都要重复这个流程：在 GE-635 上汇编、生成纸带、走到 PDP-7 前、塞入纸带、看结果、回到 GE-635 修改。这基本上是一个人可以忍受的编程体验的底线了。

![](/images/pdp-7-front-panel.jpg)

*DEC PDP-7 的前面板，1965 年。这台拥有 8K 18 位字内存的小型机是 Unix 的"子宫"。Ken Thompson 在这台机器上写了一个游戏，然后为了玩这个游戏写了 Unix。照片中可见一排排指示灯和拨动开关——这就是 1960 年代"操作计算机"的物理形态。*

但他做到了。几个月后，PDP-7 上跑起了一个简陋的操作系统：有一个文件系统、一个命令行解释器、一个汇编器、以及几个像 `rm`、`cat`、`cp` 这样的工具。Thompson 在上面修改 Space Travel 的游戏代码，觉得不够方便就再加一个工具。这套系统的灵魂是 Thompson 对"极简"近乎偏执的追求——每一个工具只做一件事，做好它，让它和其他工具配合。这个后来被叫做"Unix 哲学"的东西，最初不是哲学，是生存策略：PDP-7 的内存太小，每多一行代码都是负担。

1970 年，Brian Kernighan 为这个系统起了一个名字——Unix。它是对 Multics 的戏仿。Multics 意思是"多路信息和计算服务"，Unix 讽刺性地只取了一个音节的相似——Unics（后来改成 Unix）。一个曾志在成为"计算公用事业"的庞然大物项目失败了，它的"私生子"是一个因为想玩游戏而被顺手写出来的操作系统。

但写 Unix 的工具是汇编语言。Thompson 写了成千上万行汇编代码来构建这个操作系统的内核。汇编是直接给机器看的——每一条指令都精确对应 CPU 的一个操作。如果你想移动一个字节，你要写 `MOV`；如果你想跳转，你要写 `JMP`。它不仅难写，而且不可移植——PDP-7 的汇编换到 PDP-11 完全不通用。Thompson 心里清楚，如果 Unix 只能活在一台机器上，它终究走不远。

他需要一门语言。但他不需要 Fortran——Fortran 是为科学家准备的，是为算导弹弹道准备的。他需要的是能写操作系统的语言。于是他做了一个简陋但直接的东西：B 语言。

## Barely 够用

B 语言是 Thompson 从 BCPL 那里借来的灵感。BCPL 是 Martin Richards 在 MIT 时设计的一种系统编程语言，贝尔实验室的人很熟悉它——Multics 项目的晚期和结束后，BCPL 是小圈子里最流行的工具。

B 把 BCPL 的精髓压缩进了 PDP-7 那微不足道的内存里。说它是"压缩"毫不夸张——B 编译器一次只读取一行代码，边读边产生输出，因为它根本没有足够的内存来保存程序的整个中间表示。它生成的也不是机器指令，而是"threaded code"——一种解释执行的技术，编译器输出一串指向运行时片段的内存地址，每个片段执行一个基本操作。这意味着 B 程序的运行速度非常慢，远慢于汇编。

这些都可以忍受。真正的问题是 B 是一种"无类型"的语言。

B 只有一个数据类型，叫做"word"——机器字。在 PDP-7 上，一个 word 是 18 位。在 PDP-11 上，一个 word 是 16 位。B 语言不管这些——它把所有东西都当作 word。整数是 word，指针是 word，如果你要在 B 里处理一个字符，你得把它塞进 word 的一个角落里，然后用位运算把它取出来。这在理论上可行，在实际中让写代码的人发疯。

1970 年，贝尔实验室买了一台 DEC PDP-11。这台机器是划时代的——它采用 16 位字节寻址，这意味着内存里的每一个字节都有一个独立的地址。这在今天是常识，但在当时是巨大的进步。PDP-7 是 word-addressed——你要访问内存的第 n 个 word，而不是第 n 个字节。处理字符数据（文本）在 word-addressed 机器上是非常痛苦的，你要把一个字符打包进 word，然后手工拆解。PDP-11 的字节寻址让这一切变得自然。但自然的代价是：B 语言的"无类型"假设在 PDP-11 上暴露了致命弱点。

你以为你用手指着一个人，其实你在指他的方向乘以二。

B 语言的指针是 word 索引。你拿一个指针加一，在硬件层面它移动了一个 word（在 PDP-11 上是 2 个字节）。但如果你真正想做的是指向字节序列中的连续位置——比如字符串——你每次都要做运行时缩放转换。这意味着指针操作不再是透明的，每一次间接引用都隐含着乘除法开销。而且 B 语言处理字符的方式太笨拙了——要把一个字符串铺开成一个 word 数组，操作完再打包回去。在 byte-oriented 的机器上这样做不仅低效，而且让写代码的人觉得自己像个傻子。

更糟糕的是，B 编译器的 threaded code 技术让它的运行速度比汇编慢得多。Unix 的内核用汇编写，核心工具用汇编写——B 只能写一些外围的程序，比如 dc（桌面计算器）。到了 1971 年，Thompson 和 Ritchie 都清楚：B 语言不够用了。

改变 B 的任务落到了 Dennis Ritchie 身上。

## 实干家与设计师

Ken Thompson 和 Dennis Ritchie 是计算机史上最伟大的二人组之一。他们在 1983 年一同获得图灵奖，1998 年一同获得国家技术奖章，2011 年一同获得日本奖。但两个人的性格和做事方式截然不同。

Thompson 是新奥尔良人，从小迷恋逻辑和二进制——"在小学我就会用二进制算算术题，就是觉得着迷。"他在伯克利读的是电子工程，毕业论文导师是 Elwyn Berlekamp（组合博弈论的大家）。被贝尔实验室录用后，他马上展现出了"不按常规出牌"的天才：当项目缺少一台可用的机器时，他直接写一个操作系统；当操作系统需要一门语言时，他两个小时搓出 B 语言的编译器框架。他的驱动力不是"我想做一个伟大的系统"——是"我想现在就玩这个游戏，懒得等别人做好平台给我"。他是那种"如果世界上没有我要的工具，我就造一个"的人。他的做事哲学可以概括为一句话：够用就好，先跑起来再说。

Ritchie 完全不同。他出生在纽约布朗克斯维尔，父亲是贝尔实验室的科学家，合作写过《开关电路设计》——一本经典教科书。Ritchie 在哈佛读的是物理和应用数学，1967 年加入贝尔实验室时，博士论文还没写完（事实上他永远没有正式拿到博士学位——1968 年他完成了论文草稿，但从未提交）。他是一个安静到几乎内向的人。熟人形容他"说话轻声细语，但每句话都值得听"。他的思考方式是"让我想清楚再做"——他不追求速度，追求设计的一致性。

Thompson 像一个拿着锄头的挖掘者，看到前面有石头就砸开，不管姿势好不好看。Ritchie 像一个建筑师，他会在开工之前把蓝图画清楚，确保每个房间的尺寸都对得上。Thompson 是推动力——"我觉得我们需要更好的语言"；Ritchie 是执行力——"好，我来造它。"

这种互补化学反应的第一个成果是 B 语言的改进版本。1971 年，Ritchie 开始给 B 加入类型。他管它叫 NB——New B。

## 决定性的设计

NB 在 B 的基础上做了三件关键的事。

第一件也是最直接的一件：加入了类型系统。Ritchie 为 NB 添加了两种基本数据类型——`int` 和 `char`——以及指向它们的指针。这让处理字节和字符变得自然：`char c` 就是一个字节，`char *p` 就是指向一个字节的指针，指针加一就是下一个字节。在 PDP-11 上，这样的语义直接映射到硬件指令，没有运行时缩放，没有打包拆包。你写什么，机器就跑什么，中间没有翻译损耗。

第二件事：重写编译器。Ritchie 把 NB 的编译器从 threaded code 改为直接生成 PDP-11 机器码。这是一个巨大的性能飞跃。B 程序之所以慢，不是因为 B 语言本身有什么不可克服的缺陷，而是因为 threaded code 的解释执行方式让每条操作都要经过一个间接跳转。直接生成机器码之后，NB 程序的速度接近汇编——在某些情况下甚至超过手写汇编，因为编译器能做一些人容易忘记的优化。

第三件事是最微妙也最深远的：数组和指针的等价规则。

在 B 里，声明 `auto V[10]` 的意思是：分配一个叫 V 的变量，然后在内存里分配 10 个连续的 word，把第一个 word 的地址放进 V——V 是一个隐式指针，它在运行时指向一块内存。这是一种实现方式，但在涉及结构体（struct）时出现了问题。Ritchie 想要在 C 中加入结构体，用它来表示 Unix 的目录条目——比如一个包含 inumber 和 name 的结构体。在 B 的语义下，结构体里如果有一个数组，编译器必须为这个数组的"隐式指针"找一个藏身之处——但这块内存是实际从磁盘读入的数据，不可能在里面藏一个指针。Ritchie 被这个问题卡了很久。

他的解决方案是放弃"数组是一个隐式指针"的模型。在 NB/C 中，数组名不是指针——它在表达式中"退化"为指向第一个元素的指针。换句话说，`int a[10]` 声明了一个数组，`a` 本身不是一个变量，它不占用存储空间去存一个指针。当你写 `a[i]` 时，编译器把它翻译成 `*(a + i)`——取数组首地址，加上偏移量，然后解引用。当你写 `int *p` 时，`p[i]` 被翻译成 `*(p + i)`——完全相同的规则。数组名在表达式中自动变成了指针。这个规则在语义上让数组和指针统一了，在实现上消除了隐式指针的存储问题，在表达力上让 C 的程序员可以直接在内存地址上做算术。

这是 C 最著名的特征，也是最多初学者困惑的根源。`int a[10]`——a 是数组还是指针？答案是：在声明中是数组，在表达式中是指针。`int *p`——p 是指针，但你可以用 `p[3]` 当数组用。数组和指针在 C 里是同一枚硬币的两面。这个设计不是 Ritchie 一拍脑袋想出来的——他是被结构体的问题逼到墙角之后，找到的一个既优雅又务实的出路。

1972 年，NB 有了一个新名字。Ritchie 觉得 NB 不够好——"新 B"这个名字暗示它只是 B 的补丁。既然 B 是 BCPL 的缩写后第一个字母，那就继续用单字母吧。C。BCPL → B → C。它就像一个家族的姓，一代一代传下来，每一代都洗掉了上一代的一些杂质。

C 语言正式诞生了。

数组-指针等价规则不只是技术选择，它暴露了 C 最根本的设计哲学。在 C 的世界里，没有"高层抽象"替你屏蔽底层细节。数组名退化为指针——这意味着你要知道内存地址是什么、偏移量怎么算、指针算术是什么意思。C 不对你进行任何保护。如果你写 `a[100]` 而 `a` 只有 10 个元素，C 的编译器不会管你——它会发自内心地信任你知道自己在做什么，然后生成一条指令，访问第 100 个元素的位置。那个位置可能是另一个变量、一段代码、或者一块不属于你进程的内存。C 不会拦住你，它只会说："你让我去，我就去。"

## 信任的代价与++的来历

C 的设计原则常常被概括为"信任程序员"（trust the programmer）。这句话在 C 社区里是自豪的宣言，在安全社区里是一道挥之不去的阴影。但理解 C 为什么选择"信任"而非"保护"，必须回到它诞生的环境。

1972 年的贝尔实验室，Ritchie 和 Thompson 是一群系统程序员。他们是写操作系统的，不是写应用的。操作系统需要做的事情——直接操作硬件地址、管理内存布局、在进程间传递数据结构——全都是和机器的底层细节打交道的。如果 C 在每一次指针操作时都要做边界检查，Unix 内核的速度就会降到一个不可接受的程度。而且，在那个时代，没有"缓冲区溢出"这个词——因为还没有足够多的恶意攻击者在网上搜索漏洞。计算机还是研究机构里的大型设备，用的人经过严格筛选，"安全"不是设计的第一优先级。

效率、控制、简洁——这些才是。

这种哲学最生动地体现在 Thompson 发明的 `++` 和 `--` 运算符上。人们经常以为这两个运算符是为了利用 PDP-11 的自动递增寻址模式而设计的——因为 PDP-11 确实有"间接访问后把地址加一"的硬件指令。但 Ritchie 在 1993 年的论文里专门澄清过：历史顺序是反的。`++` 和 `--` 在 B 语言时代就有了，早于 PDP-11。它们最初是为了利用 PDP-7 的几个"自动递增寄存器"——那几个寄存器在被间接引用时会自动加一。但 Thompson 的贡献是把这个硬件特性推广成了通用的语言运算符，而且设计了前缀和后缀两种形式——`++x`（先加后用）和 `x++`（先用后加）。这个细节的优雅在于：它把一个微处理器层面的寻址优化提炼成了程序员可以直接使用的语义抽象。这正体现了 C 的设计精神——底层硬件的特性不应该被锁在汇编语言里，高级语言也能拥抱它。

`++` 和 `--` 不是 C 中唯一从汇编世界借来的武器。位运算——`&`、`|`、`^`、`<<`、`>>`——直接操作一个整数的二进制位。`*` 和 `&` 让指针的声明和间接访问在语法上对称。赋值运算符 `+=` 的写法来自 ALGOL 68，通过 Doug McIlroy 的 TMG 编译器间接传入。C 没有发明这些东西，但它做了一件更重要的事：把它组装成一个连贯的、足够表达整个操作系统的语言。

到了 1972 年底，C 已经有了类型系统、指针算术、结构体、`++` 和 `--`、位运算、以及一个能直接生成 PDP-11 机器码的编译器。它还不够大——没有浮点支持（PDP-11 的浮点协处理器还没到货），没有 `union`，没有 `unsigned`，没有 `void`，没有 `enum`。但它已经够用了。够用的意思是——可以用它来写 Unix。

## 1973 年夏天

计算机史上最重要的三个月之一，是 1973 年的夏天。

Thompson 和 Ritchie 做了一个在当时堪称冒险的决定：用 C 重写 Unix 内核。

要知道，Unix 当时已经在 PDP-11 上稳定运行了。内核是用汇编写的——每一条指令都经过精心优化，性能很好。重写意味着一切都要从头开始，而且 C 编译器的代码生成质量还是个未知数——虽然 NB 已经证明了接近汇编的速度，但没有人在这么大的项目上验证过。如果 C 生成的代码不够快，整个操作系统的性能会倒退，甚至可能跑不动。

但他们做了。Thompson 用 C 写了调度器、内存管理、文件系统；Ritchie 用 C 写了 I/O 系统和大部分设备驱动。1973 年底，Unix 内核的绝大部分代码已经用 C 重写完毕。那个夏天之后，Unix 不再是一个"PDP-11 的汇编操作系统"——它变成了"一个可以用 C 编译并在任何有 C 编译器的机器上跑的操作系统"。

这个转变的意义怎么强调都不过分。在 C 之前，操作系统只能用汇编写。在 C 之后，操作系统可以"可移植"了。1977 年，贝尔实验室把 Unix 移植到了 Interdata 8/32——一台完全不同的计算机架构上。移植过程远比想象的顺利：编译 C 代码、解决架构差异、重新编译。不需要重写内核。不需要逐行翻汇编。不需要三个月。

"可移植操作系统"这个概念在 1973 年之前几乎是不存在的。每个操作系统都绑定在它的硬件上。IBM 的操作系统只能跑在 IBM 机器上，DEC 的操作系统只能跑在 DEC 机器上。如果你换了硬件，你换的不只是机器——你换的是整个软件生态。C 和 Unix 第一次打破了这种绑定。你写一次代码，可以在 VAX、Interdata、IBM 360 上编译运行。这个想法在今天听起来是天经地义的——"跨平台"在 2026 年是基本要求。但在 1973 年，这是革命性的。

![](/images/thompson-ritchie-pdp11-1973.jpg)

*1973 年，Dennis Ritchie（左）和 Ken Thompson（右）在贝尔实验室的 PDP-11 前。这是计算机史上最有名的合影之一。就在这一年夏天，他们用 C 重写了 Unix 内核——操作系统第一次可以用高级语言写。两人背后的 PDP-11 面板上的指示灯和开关，代表了那个时代"计算机"的物理形态。*

1973 年，Ritchie 和 Thompson 在 SOSP（操作系统原理研讨会）上发表了那篇著名的论文《The UNIX Time-Sharing System》。这是 Unix 第一次正式向学术界亮相。论文是用打字机打的，措辞简洁到几乎没有形容词，实验数据朴素得令人发笑——"Unix 内核占 41K 字节"。但它包含了一个操作系统至今最重要的若干概念：进程、文件系统、管道、Shell。更关键的是，它包含了一门语言。C 作为 Unix 的实现语言被正式写进了文献——"The system is written in a high-level language called C"（本系统用一种名为 C 的高级语言编写）。

这句话的重力是惊人的。当一个操作系统论文说"我们用高级语言写的"——这在 1973 年相当于在说"我们不用马蹄铁了，我们用了轮子"。

## 228 页

![](/images/kr-c-book-cover-first-edition.svg)

*《The C Programming Language》第一版（1978），228 页。它定义了 C 在程序员心中的形象。在 ANSI 标准化之前，它就是标准。封面朴素到极致——白色背景，黑色大字。这个设计本身就像 C 语言：不加修饰，相信内容本身的分量。*

1978 年，Brian Kernighan 和 Dennis Ritchie 出版了《The C Programming Language》。228 页。它的封面是一本白色的书，书名用大写字母写着 THE C PROGRAMMING LANGUAGE，字下面是一行淡蓝色的分隔线。这个设计朴素到今天的出版社会拒绝——但它卖了超过一百万册。

这本书的写法是 Kernighan 的主意。他认为，C 是一门小语言，一本大书是对它的不尊重。"没有人愿意花时间去读一本 600 页的编程书，"他说。于是他们只写了 228 页——"再多一页都是对 C 语言的小视。"

Kernighan 写了几乎全部正文，Ritchie 写了附录 A（参考手册）和附录 B（标准库）。分工明确：正文是教程，带你从"hello, world"走到指针、结构体、文件操作；附录是参考，给已经会写 C 的人查语法。这种"教程+参考手册"的结构后来成为几乎所有编程书的模板。但在 1978 年，它是新鲜的——没有谁在教一门语言的时候既假设你一无所知（从头开始教你），又假设你什么都知道（附录精确到语法的每一个细节）。

这本书第一个例子就是 `main() { printf("hello, world\n"); }`。11 个单词，三行代码，一个函数调用。它不是为了展示 printf 的用法，不是为了让读者看到如何声明变量——"hello, world" 在这个上下文里的真正意义是：看，你只写了三行代码，程序就跑起来了。你写了一个完整的程序。你不需要了解链接器、加载器、段定义——C 的教科书从第一次翻开就让你体验"我在写代码"的成就感。这个传统从 K&R 开始，影响到后来几乎每一种语言的教科书。

但 K&R 的真正分量在于：在 ANSI 标准化之前，它就是标准。

1980 年代初，C 的编译器越来越多，不同编译器之间出现了微妙的差异。K&R 的第一版——一本 228 页的书——成了仲裁者。如果一个编译器在这个问题上跟 K&R 说的不一样，那编译器就是错的。一个非正式组织"不和"的程序员在 Usenet 上争论一个语法细节，最后的裁判是谁？翻开书，找到附录 A 的某一段。书上是这样写的，那就这样办。没有任何权威机构宣布这件事，但整个社区默认了：K&R 说的算。

这种状态一直持续到 1989 年 ANSI C 标准正式发布。在那之前，C 是"一个被一本书定义的语言"。这不是形容，是事实。

## 每一个角落

C 赢了。它赢得如此彻底，以至于大多数人意识不到它的存在。

Linux 内核——用 C。Windows 内核——用 C。macOS 内核——用 C。iOS 和 Android 的内核——用 C。Python 的解释器 CPython——用 C。Ruby 的 MRI 解释器——用 C。PHP 的解释器——用 C。Redis 数据库——用 C。SQLite——用 C。Nginx 和 Apache Web 服务器——用 C。OpenSSH——用 C。OpenSSL——用 C。curl——用 C。Git——用 C。Vim——用 C。Emacs——用 C。你使用的几乎每一个互联网服务的底层基础设施——DNS 服务器、负载均衡器、路由器操作系统——要么直接用 C 写，要么在 C 的运行时会系统之上运行。

C 是计算世界的混凝土。没有人看到它，但没有它任何东西都立不住。

但这个胜利是有代价的。

"信任程序员"的另一面是——程序员会出错。缓冲区溢出、use-after-free、野指针、内存泄漏——半个世纪以来，这些 C 特有的问题一直是计算机安全噩梦的根源。1988 年的 Morris Worm 利用了一个 C 函数 `gets()` 的缓冲区溢出问题——这个函数甚至在 C 标准里都不建议使用，但它存在于数以万计的代码库中。2014 年的 Heartbleed 漏洞——OpenSSL 的心脏出血漏洞——本质是一个 C 的内存边界检查缺失。至今，微软和谷歌的研究表明，操作系统和浏览器中的所有严重安全漏洞，约 70% 是内存安全问题，根源几乎都是 C/C++ 不安全的指针操作。

这不是 C 的缺陷——这是 C 的设计选择。创建一个既不保护你也不限制你的语言，是它最大的力量，也是它最深的代价。你不能在不写指针的情况下用 C 做系统编程，你不能在不面对内存问题的情况下用 C 做高性能计算。C 给你所有的控制权，但把安全责任完全交给你。在 1972 年，这是一群互相信任的贝尔实验室研究员之间合理的约定。在 2026 年，全球有数百万程序员在写 C——不是每个人都值得被信任。

C 的成功甚至催生了它的挑战者。2015 年，Mozilla 发布了 Rust 1.0——一门承诺"没有垃圾回收的内存安全系统编程"的语言。Rust 的所有权系统在编译时检查内存的谁借了谁，从根源上消除了缓冲区溢出和数据竞争。2022 年，Linux 内核开始接纳 Rust 代码。美国国防部高级研究计划局和网络安全与基础设施安全局都公开建议：新项目中逐渐放弃 C/C++，转向内存安全语言。2024 年，白宫发布了《关于内存安全的报告》。C 的替代者来了——但 Rust 的编译器本身就是用 C 写的，Rust 运行时的底层接口依然是 C ABI。C 不会消失，它会变成 Rust 下面的那层。

这很像 C 本身的历史。C 没有完全消除汇编——高级语言下面总有一层更底层的东西。编译器可以生成机器码，但写好编译器的人需要理解机器。在你用 Python 写 `print("hello")` 的时候，Python 解释器（CPython，C 写的）在调用 `printf`（C 标准库函数），而 `printf` 最终会通过系统调用（也是 C 写的）请求内核（还是 C 写的）在终端上输出那几个字节。每一层都是 C。

## 计算机走出机房

Fortran 让科学家不再排队等程序员。Lisp 让机器处理符号而非数字。C 让写操作系统不再依赖汇编。

这三步完成了计算机从"实验室工具"到"基础设施"的转变。Fortran 把计算机从"只有少数受过特殊训练的人能用"变成了"科学家也能用"；Lisp 把计算机从"高速计算器"变成了"可以对话的符号处理机"；C 把计算机从"必须用汇编写系统软件"变成了"可以用高级语言写一切"——包括写其他高级语言的解释器。

C 让 Unix 可移植。Unix 的传播（通过 BSD、System V、Linux）让互联网成为可能——因为互联网的服务器几乎全部跑在 Unix-like 系统上。Linux 内核是 C 写的。Apache 是 C 写的。MySQL 是 C 写的。BIND（DNS 服务器）是 C 写的。sendmail 和 Postfix（邮件服务器）是 C 写的。互联网的每一层——传输、路由、服务、数据库——全部建立在 C 代码之上。

当 Ritchie 在 2011 年去世时，他的讣告被 Steve Jobs 的报道淹没。这不是对 Ritchie 的不尊重，而是对 C 的"不尊重"的终极证明——C 太成功了，成功到没有人注意到它存在。就像没有人注意到你正在呼吸的空气。没有人注意到你脚下的混凝土。

计算机历史学家 Paul Ceruzzi 说得好："Ritchie 的名字不是家喻户晓的名字。但如果你有一台显微镜，能看见计算机内部，你会在每一个地方看到他的作品。"

2011 年 5 月，Ritchie 和 Thompson 一起在日本东京领取了日本奖。那是 Ritchie 最后一次公开露面。他穿着西装，身形消瘦——多年与前列腺癌和心脏病的抗争让他看起来比实际年龄衰老。照片里的他站在讲台上，表情平静，目光温和。五个月后，他走了。

世界没有停下来。你的手机还在跑 Linux。你的 Wi-Fi 路由器还在跑一个嵌入式操作系统。你从口袋里掏出设备，点亮屏幕的那一刻，C 代码就开始执行。每一毫秒——调度、中断、内存分配、网络包处理——都是几十亿条从 C 编译过来的机器指令在不可见的地方默默工作。

Fortran 打开了第一扇门。Lisp 打开了第二扇。C 打开了第三扇——门后的世界，叫"计算机不再是一台机器，它是基础设施。"

如果 Fortran 是数学的翻译，Lisp 是符号的递归，那么 C 就是 Unix 的血液——它流在每一行系统代码里，流在每一次内核调用里，流在每一个 `printf` 里。它流淌了五十年，还会继续流下去。

## 人物

![](/images/dennis-ritchie-young.jpg)

*Dennis Ritchie（1941–2011），C 语言的设计者，Unix 的共同创造者。布朗克斯出生，哈佛物理和应用数学出身，博士论文未完成就加入了贝尔实验室。安静、深思熟虑，是"做之前先想清楚"的设计者。1983 年获图灵奖，2011 年日本奖。去世同周被 Steve Jobs 的新闻淹没——但他的代码在所有设备里运行。*

![](/images/ken-thompson-young.jpg)

*Ken Thompson（1943–），Unix 的创造者，B 语言的发明者，C 的共同开发者。新奥尔良人，从小迷二进制和逻辑。他是"如果我想要一个工具，我就写一个"的实干家——为了玩 Space Travel 游戏写了 Unix，为了让 Unix 能写高级语言催生了 C。后来还发明了 UTF-8、设计了 Go 语言。2026 年仍在世，在 Google 工作。*

![](/images/brian-kernighan-portrait.jpg)

*Brian Kernighan（1942–），贝尔实验室研究员，《The C Programming Language》的作者——他写了几乎全部正文，Ritchie 写附录。'Hello, World' 教学传统的发明者。后来还发明了 AWK 语言（其中的 K 就是 Kernighan）。2026 年仍在普林斯顿大学任教。*
