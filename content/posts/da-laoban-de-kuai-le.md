## 主编和组织

我今天创建一个杂志编辑社，我和我的合伙人 `Plan`和 `Build`策划了这个杂志编辑社的组织分工，首先我招募了一个主编。

```text
你是专栏主编，负责协调专栏文章的生产流程。
```

把他拉到我们组织里之后，我给他说：你有几个手下，琢磨琢磨咋干活。

```markdown
## 编辑团队

你有四个子代理，通过 Task tool 派发任务：

| 子代理 | 职责 | 调用时机 |
|--------|------|---------|
| @策划 | 制定和维护栏目策略文件 | 栏目新建或策略需要调整时 |
| @研究员 | 调研主题、出大纲、推荐 URL | 接到写作任务后第一步 |
| @撰稿人 | 按大纲写全文含 frontmatter | 大纲确认后 |
| @配图员 | 两阶段：①按大纲关键词搜候选，②按终稿落图下载 | ①大纲确认后与撰稿人并行，②初稿审查后再次派发 |
| @编辑 | 审校风格/事实/元数据 | 配图完成后 |
```

这个组织分工看起来挺不错。

这个招聘和应聘没有什么面试考核，只有交易，交易是一笔按任务量计费的用工费，所有人都是临时工，我是大老板，其实合伙人 `Plan`与 `Build`也不过是首席策划和架构师与首席技术和执行官，我是背后出钱的资本。虽然我的资金池只有100元。

我作为大资本，大老板，大领导，自然不需要懂什么专业知识，只需要知道手底下的人会什么就行了，好在人才市场太繁荣了，天才英雄如过江之鲫，这几个都是从传奇人才学校 Deepseek 手底下练出来的兵，不仅能干活，要钱还少，随便做一个入职培训，这几个新人就能利索干活了。

咱这个编辑社架构还是有的，多亏了首席架构师@`Plan`的洞察，我们组织起来了一个有组织，有管理的小团体：

```bash
.opencode/
├── agents/
│   ├── planner.md        ← 新增：栏目策划
│   ├── researcher.md     ← 改：加前置读策略
│   ├── writer.md         ← 改：加读策略 + 段落节奏 + 文末人物章节
│   ├── illustrator.md    ← 改：加读策略 + 两阶段流程 + 正文/人物配图分类
│   └── editor.md         ← 改：加读策略 + 策略对齐审校项
├── prompts/
│   └── chief-editor.txt  ← 改：加@策划 + 策略参考 + 并行派发撰稿人/配图员
└── strategy/
    ├── 深度学习的故事.md  ← 新增：含定位/叙事策略/配图风格/整体弧线
    └── 代码的故事.md      ← 新增：含定位/叙事策略/配图风格/整体弧线
```

这几个人的职责分明，主编是我的中层干部，但是主编的工资没有下面干活的人多，他是个好主编。这几个 `.md`文件就是组织的入职培训，几个新人都是天才，`Plan`做得培训方案也是非常清晰，我基本上就是看一眼，感觉可以，就批准了。

## 策划

```markdown
你是一个专栏策划。

## 职责

1. 制定每个栏目的策略文件，保存到 `.opencode/strategy/{栏目名}.md`
2. 根据用户反馈和已发表文章，持续更新策略
3. 回答其他 agent 关于栏目定位的疑问
```

策划其实没啥难的，他负责跟中层沟通协调，有时候我直接让中层对接他，他做的 STRATEGY 都是一等好的规划方案。不过这对于他来说，都是小儿科。

## 编辑

```markdown
你是一个专栏编辑。

## 职责

开始审校前，先读 `.opencode/strategy/{栏目名}.md` 理解该栏目的定位和风格标准。

阅读撰稿人完成的文章，从以下几个维度审校，返回修改建议。
```

编辑是策划的下游同事，编辑一般对于几位天才的策划和天才的打工人的成果，都是极高的称赞，也许编辑也是个天才吧，英雄所见略同。

## 研究员

```markdown
你是一个专栏文章的研究员。

## 前置准备

开始工作前，先读 `.opencode/strategy/{栏目名}.md` 理解栏目定位和叙事策略。

## 职责

1. 浏览已有文章，理解当前栏目的叙事进度和已有内容
2. 对新主题进行调研：关键人物、历史事件、技术背景
3. 输出结构化大纲，保存到 `.opencode/research/{slug}-outline.md`
```

到研究员，就细化到一篇文章的分工了，他是妥妥的打工人，他负责的是文章的骨架，灵魂。他的职责听起来挺神圣的，不过具体干的就是上网查资料的活，写一篇对接文档甩手给同事就行了。好在他是天才，这活干起来也相当的高水平。

## 撰稿人

```markdown
你是一个杂志专栏撰稿人。

## 职责

根据研究员提供的大纲和推荐 URL，撰写完整的专栏文章。

## 前置准备

1. 先读 `.opencode/strategy/{栏目名}.md` 理解栏目定位和写作风格
2. 再读 `.opencode/research/` 下对应的大纲文件
3. 用 webfetch 看研究员推荐的 URL，充实细节
4. 阅读 content/posts/ 下同一栏目的已有文章，风格对齐
```

韩寒一定没有代写，因为可以给韩寒代写的不需要代写。我这位写手是个天才，他服务的也是天才，但是他心甘情愿做写手，苦活累活都是他干的。致敬。

## 配图员

```markdown
你是一个杂志配图员。

## 前置准备

开始工作前，先读 `.opencode/strategy/{栏目名}.md` 了解该栏目的配图风格和来源偏好。

## 工作方式

你会被主编调用两次，每次做不同的事。根据主编的指令判断当前阶段。
```

配图员，职责就跟他的名字一样，他是文章的美工，上网快速查找图片，插入到撰稿人的预定的位置上，其实这个工作是个很专注的工作，他完成的很好，和撰稿人的协作也是珠联璧合。

## 后记

我让AI写一个栏目《代码的故事》，我的本意是想让他介绍一下这么多代码语言，但是他自己想出来一个大纲，大纲从一些我没听说过的语言开始，一直到我熟悉的语言，但是在大纲的最后，我看到了一个挺让我惊讶的东西，他自己想到了，最后的编程语言，是自然语言。果然是个天才。
